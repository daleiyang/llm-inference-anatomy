两个融合算子：RMSNorm 与 online softmax

第 10 章练的是"把长数组归约成标量"，归约就是终点。 这里练的是归约之后那一步 —— 拿归约结果回头缩放整行。 「回头」是要么再读一次显存，要么把数据留在片上，两条路差 1.5 到 2 倍带宽。 SGEMM 那一章在 roofline 的左半边（算力密集）， 这两个算子在右半边（访存密集），指标从「占峰值算力」换成 MBU。 而 online softmax 的那三行递推， 就是 FlashAttention 的全部数学内核 —— 在这里吃透，能省下 04 阶段（FlashAttention 前向）的两天。

实测（RTX 4090 · 2026-10-01）：寄存器驻留的 N3/N4 与 S3/S4 全部收在峰值带宽的 90–91%（MBU），相对基线（N1 两趟 / S1 三趟）快 1.51× 和 1.70×。 开跑前写死的十四条预测成立 9 条；落空的 5 条全部栽在同一件事上 —— 字节账算的是「指令发出的字节」，而耗时取决于「到 DRAM 的字节」，中间隔着一层 72 MiB 的 L2。 融合省带宽的机制不是少发访存指令，而是把重用距离压进 cache 装得下的范围 —— 见 §9。

为什么是这两个算子↑

SGEMM 那一整章练的是 roofline 的左半边：算力密集，看「占峰值算力」。 这两个算子在右半边：访存密集，看 MBU。 同一张 roofline 图，两端各来一次，这套方法才算学完整。 而且它们不是玩具——RMSNorm 是 Qwen2.5 每层都要调两次的真算子， online softmax 的那三行递推就是 FlashAttention 的全部数学内核。

一、第 10 章练的是归约，这里练的是「归约之后呢」↑

第 10 章 R1–R6 解决的问题是「把一个长数组变成一个标量」， 归约就是终点，算完 atomicAdd 出去就结束了。

真实算子里归约几乎从来不是终点。 RMSNorm 要先把一行求平方和，然后立刻拿这个和回头去缩放这一行的每个元素； softmax 要先求出一行的 max 和 exp 和，然后回头把每个元素除掉。 归约是中间步骤，"回头"才是花钱的地方。

这一句差别，决定了两处写法必须改

① 归约结果要广播给全 block，不能只汇到 0 号 lane。 R6 用 __shfl_down_sync，因为只有 0 号 lane 需要结果； 这里 256 个线程每一个都要拿归一化因子去缩放自己手里的元素， 所以要换成 __shfl_xor_sync（蝶形），归约完人手一份。

② 「回头」意味着要么再读一次显存，要么把数据留在片上。 这两条路的带宽差 1.5 倍到 2 倍， 而这就是本文四级阶梯里最值钱的那一级。

二、它们在 Qwen2.5-7B 里的真实位置↑

模型参数取自 Qwen2.5-7B 结构拆解： hidden 3584 · 28 层 · 28 Q 头 / 4 KV 头 · head_dim 128 · ffn 18944 · vocab 152064。

先说一句诚实话：在 7B 的 decode 里，这两个算子都不是瓶颈。 decode 一个 token，57 次 RMSNorm 一共搬 1.6 MB， 按 1008 GB/s 算是 1.6 微秒；而同一步要把 15 GB 的权重读一遍，要 15 毫秒。 RMSNorm 占万分之一。

这就是 FlashAttention 存在的理由。 它的做法不是"把 softmax kernel 写得更快"， 而是根本不把打分矩阵写进显存——在 shared memory 里分块算完就地消掉。 而"分块算 softmax"这件事能成立， 唯一的前提就是 §5 要推的那三行递推式。 所以本文的 s3 会输给"没有 softmax kernel"，这不是失败，是终点的指路牌。

先把 16N 的单位说清楚

16N 的单位是「字节 / 行」，不是「访问 16 次」。 N 是一行的元素个数，fp32 一个元素 4 字节， 朴素三趟要把整行过显存 4 遍（3 读 + 1 写），所以 16N = 4 趟 × 4 字节 × N。

这本账只数必须经过显存（HBM）的字节—— 每行那 4 字节的 mx[] / sm[] 中间数组待在 L2 里，不计入。

图 1 · 16N 怎么变成 209 ms。 上半：一层的打分矩阵是 28 个 4096×4096 的头（1.879 GB）， softmax 沿 key 维做，所以行长 N = 4096、行数 M = 28 × 4096 = 114,688。 下半：每行 16N = 64 KB，乘行数得 7.516 GB/层，除 4090 的峰值带宽 1008 GB/s 得 7.46 ms/层，乘 28 层得 209 ms。 注意这是 MBU = 100% 的理论下界——假设一次 exp 都不要钱，现实只会更慢。

一、RMSNorm：12N 还是 8N↑

y = x · rsqrt(mean(x²) + eps) · w        // N = 3584

一句话：把一行（一个 token 的 3584 维向量）整体缩放到固定长度，再逐维乘一个学出来的增益。 公式里只有三个动作 —— 求均方、取倒数平方根、逐维相乘。

图 2 · RMSNorm 全部内容就是这三步。 ①→② 整行只做一件事：乘同一个标量 r（这组数据 r ≈ 0.5），所以形状分毫不变，只是整体矮了一半。 归一之后整行的模恒等于 √N（N = 3584 时约 59.87）—— 不管输入多大多小，出来的长度都一样， 这正是「Norm」二字的含义。②→③ 乘 w 才改变形状，而 w 是训练学出来的， 对这一行来说是个常量。

和 LayerNorm 的区别：RMSNorm 把「减均值」整个砍掉了

砍掉「减均值」是 Zhang & Sennrich 2019 的发现： 效果几乎不掉，却省掉一个统计量和一遍减法。 今天的主流模型（Llama、Qwen、Mistral）全部用 RMSNorm。

这个算子为什么会有 12N 和 8N 之争

关键在 r：它是整行归约出来的一个标量， 必须把整行看完才能算出来；可算出来之后，又要拿它去缩放整行的每一个元素。 于是「回头」这一步就有两条路： 要么把 x 从显存再读一遍（12N），要么在第一遍读的时候就把它留在寄存器里（8N）。 下面这张表的四级台阶，量的就是这件事。

二、softmax：16N / 12N / 8N↑

softmax(x)_i = exp(x_i − m) / Σ_j exp(x_j − m)      // m = max(x)，N = 上下文长度

一句话：把一行任意实数变成一个概率分布 —— 全为正、加起来等于 1、大小顺序不变。 注意力里这一行是「这个 query 对 N 个 key 的打分」， softmax 之后就成了「该把多少注意力分给每个 key」。

图 3 · softmax 也是「先归约、再回头缩放整行」，只是归约出两个标量。 ①→② exp 把所有数变成正数，并把差距按指数放大： 输入里 1.5 和 0.8 只差 0.7，出来却是 1.00 和 0.50，差了一倍。 ②→③ 除以同一个标量 s —— 整行乘同一个数、形状分毫不变， 和 图 2 的 ①→② 是同一件事。 ③ 画成一条 总宽 = 1 的带子：12 段宽度就是 12 个概率，正好铺满，这就是「归一化」。 均匀分布该是 8.3%，这里最高 23.4%、最低 1.2%。

softmax 为什么比 RMSNorm 多一级台阶

RMSNorm 的归约量 mean(x²) 一趟就能累出来； 而 softmax 的 s = Σ exp(x − m) 要先知道 m 才能开始算。 于是朴素实现被迫扫三趟：求 max → 求 exp 和 → 归一化， 加上写回一共 16N。

而这一趟是可以省掉的 —— 靠的不是代码技巧，是一个数学改写：online 递推让 max 和 sum 在一趟里同时推进。 这就是下面 S1 → S2 那一级（16N → 12N）的全部来源，推导在 §5。

注意 S1 → S2 省掉的那一趟，靠的不是代码技巧，是一个数学改写。 朴素做法必须先看完整行才知道 max，才能开始算 exp 和； online 递推让两者可以同时推进。 推导在 §5。

三、一个必须分清的区别：融合 ≠ 省带宽↑

N2 这一级是故意留的陷阱

N1 是两个 kernel，N2 是一个 kernel —— 按通常的说法，N2 就是"融合版"了。 可它的字节数和 N1 一模一样，都是 12N。

因为 N2 虽然只发射了一次 kernel， 但它在算完 rstd 之后，又从 global memory 把同一行 x 读了第二遍。 显存流量一个字节都没省。 省下的只有一次 kernel launch（几微秒） 和 rstd 数组的往返（4M 字节）。

真正省带宽的是 N2 → N3：把 x 留在寄存器里。 "融合"这个词在工程讨论里被用得很松， 有人指"合并 kernel"，有人指"数据留在片上"。 这两件事的收益差了整整一个数量级， 而 N1/N2/N3 三级并排跑一次，就把它们分得清清楚楚。

这正是 SGEMM 那一章的方法论

每一级只动一个变量。 N1→N2 只动 kernel 个数（字节不变）； N2→N3 只动数据驻留位置（字节减 1/3）；N3→N4 只动访存指令宽度（字节不变）。 三级下来，每一份收益归谁所有，没有含糊的余地。

积木从第 10 章的 R6 到这里↑

归约代码可以直接搬第 10 章 R6 的那一套，但有一个字要改。

一、down 还是 xor↑

// 第 10 章 R6：结果只汇到 0 号 lane，其余 lane 的值是垃圾
for (int off = 16; off > 0; off >>= 1)
    sum += __shfl_down_sync(0xffffffffu, sum, off);
if (lane == 0) atomicAdd(output, sum);        // 只有它要用

// 这里：256 个线程每一个都要拿归一化因子去缩放自己手上的元素
for (int off = 16; off > 0; off >>= 1)
    v += __shfl_xor_sync(0xffffffffu, v, off);
// 五轮之后每个 lane 手里都是全和 —— 少一个线程知道都不行

先把这条指令本身说清楚

一个 warp 有 32 个 lane，每个 lane 手里的 v 是它自己的一份寄存器， 彼此看不见。 要让 lane 之间交换数据，常规办法是绕一圈 shared memory： 我写进去、__syncthreads()、你读出来。 shuffle 指令是唯一的捷径 —— 它让一个 lane 直接读另一个 lane 的寄存器，不过 shared、不过显存、不用同步。

而 __shfl_xor_sync 做的事只有一件： 把伙伴手里的 v 取回来交给我。 它不做加法。代码里那个 += 是你自己写的。 这是这行代码最容易看错的地方 —— 下面第一张图就是拆这一步。

图 5 · 这条指令只负责「取」，不负责「算」。 第一行是每个 lane 自己寄存器里的 v；一条 __shfl_xor_sync(..., v, 4) 之后， 每个 lane 拿到的是伙伴那一份 v（第二行）；第三行的加法是 += 自己做的。 把这三步分开看，v += __shfl_xor_sync(0xffffffffu, v, off) 就不再神秘了。

四个位置分别是什么
位置写的是含义
第 1 个参数0xffffffffu 参与掩码：32 个 1，表示这个 warp 的 32 个 lane 全部参与。 哪一位是 0，就表示那个 lane 不参与，读它是未定义行为
第 2 个参数v 我贡献出去的值 —— 伙伴会读到我的这一份。 它同时也是我自己要用的那个变量，但在这个位置上的角色是「给出去」
第 3 个参数off 伙伴是谁：伙伴的 lane 号 = 我的 lane 号 ^ off。 这是 xor 版和 down 版唯一的区别（后者是 + off）
返回值— 伙伴那一份 v。不是和， 也不是我自己的值 —— 要得到和，必须自己写 +=

为什么函数名后面非要带 _sync

Volta（sm_70）之后 GPU 有了独立线程调度，同一个 warp 里的 32 个 lane 不再保证锁步执行。 分支之后它们可能停在不同的指令上。 这时候「读伙伴的寄存器」就必须先说清楚：哪些 lane 要在这条指令上会合。 掩码就是在回答这个问题，硬件据此把它们重新收拢。

所以不带 _sync 的老版本 __shfl_xor 已经废弃 —— 它在新架构上会安静地读到垃圾。 另外：掩码里列出的 lane 必须全部真的执行到这一句， 把它写进一个只有一半 lane 会进的 if 里，同样是未定义行为。

为什么 xor 一定是「两两互读」

因为异或是对合运算：(lane ^ off) ^ off == lane。 我算出伙伴是 p，那么 p 按同一条规则算出来的伙伴正好是我。 于是「我读你、你读我」天然成对，一条指令就完成一次双向交换。 

// xor：对合，成对
lane 2 的伙伴 = 2 ^ 4 = 6
lane 6 的伙伴 = 6 ^ 4 = 2   // 正好读回来，互为伙伴

// down：加法不对合，单向
lane 2 读 lane 2 + 4 = 6
lane 6 读 lane 6 + 4 = 10  // 不是 2，而是往更远处要 —— 所以是漏斗，不是交换

二、block 级两段式归约↑

BLOCK = 256 = 8 个 warp。 warp 内部用 shuffle 解决，跨 warp 只能走 shared。 

__inline__ __device__ float blockReduceSum(float v, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;

    v = warpReduceSum(v);                      // ① 每个 warp 各归各的
    if (lane == 0) smem[warp] = v;             // ② 8 个结果落进 shared
    __syncthreads();                           // ③ 等 8 个都写完

    v = (threadIdx.x < (BLOCK >> 5)) ? smem[lane] : 0.0f;
    if (warp == 0) v = warpReduceSum(v);       // ④ 0 号 warp 把 8 个归成 1 个

    if (threadIdx.x == 0) smem[0] = v;         // ⑤ 放回 shared
    __syncthreads();                           // ⑥ 等它写完
    return smem[0];                            // ⑦ 全 block 一起读走
}

为什么是两个 __syncthreads()，一个都不能少

③ 保证"写 shared"发生在"读 shared"之前。 少了它，0 号 warp 可能在 7 号 warp 还没写完时就去读 smem[7]。

⑥ 保证"0 号 warp 写完最终值"发生在"其余 warp 读它"之前。 少了它，1–7 号 warp 读到的是 ② 留下的旧值（那是某个 warp 的部分和，不是全和）。

这类错误不会崩溃、不会报错， 只会让结果偏一点点。 所以 run_fused.sh 里专门留了 compute-sanitizer --tool racecheck 那一步（它到底在查什么，见 §8 · 三）。

第 ④ 步那个 : 0.0f 不是随便填的 —— 它是加法的幺元。 8 个 warp 只用了前 8 个 lane，其余 24 个 lane 必须喂一个 "参与运算但不改变结果"的值。求和用 0，求最大值用 -FLT_MAX， 求乘积就得用 1。填错幺元是这类代码最隐蔽的一种错。

三、联合归约：把 (m, s) 当成一个整体↑

online softmax 要同时归约两个量，而且它们不是各归各的—— s 的合并方式依赖 m。 

__inline__ __device__ void warpReduceMaxSum(float &m, float &s) {
    for (int off = 16; off > 0; off >>= 1) {
        float m_o = __shfl_xor_sync(0xffffffffu, m, off);   // 伙伴的 max
        float s_o = __shfl_xor_sync(0xffffffffu, s, off);   // 伙伴的 sum
        float m_n = fmaxf(m, m_o);                          // 新的公共基准
        s = s * __expf(m - m_n) + s_o * __expf(m_o - m_n);
        m = m_n;
    }
}

两边都先换算到新基准 m_n 再相加。 谁的 max 小，谁的 exp 就是个小于 1 的数，把它的和缩下去； 两边相等时两个 exp 都是 1，退化成普通加法。

先回答两个最容易卡住的疑问

「这循环只跑了一次？」——不，它跑 5 轮：off 依次是 16、8、4、2、1， 和 §3 · 一 图 6 是同一个蝶形， 只是每个格子从「一个标量」变成了「一对 (m, s)」， 每轮也从 1 条 shuffle 变成 2 条（m 一条、s 一条）。

「一轮只碰一个伙伴，怎么可能覆盖 32 个 lane？」 因为伙伴递过来的从来不是它自己那一个元素， 而是它已经汇总好的一摞。 第 k 轮结束时，每个 lane 手里的 (m, s) 已经概括了 2k 个 lane；2⁵ = 32，正好覆盖全 warp。下面第二张图就是拆这个。

一、循环体那一行到底在算什么

每个 lane 手里的 s 不是一个裸和，而是「以我自己的 m 为基准」的和： s = Σ exp(x_j − m)。 我和伙伴的 m 通常不一样， 也就是说两个 s 量纲不同，直接相加是错的。 所以必须先把两边都换算到同一个新基准 m_n = max(m, m_o) 上，再相加 —— 这就是那一行干的全部事情。

图 8 · 「换算到新基准再相加」，一行代码三件事。 s 和 s_o 各自以不同的 m 为基准，量纲不同，不能直接加； 取 m_n = max 之后，两边各乘一个 exp(自己的 m − m_n) 把量纲对齐，再相加。 基准大的那一边因子恰好是 exp(0) = 1，所以真正被缩的永远只有小的那一边。 两边 m 相等时两个因子都是 1，整行退化成普通加法。

二、一轮只碰一个伙伴，为什么能覆盖全 warp

图 9 · 伙伴递过来的是「一摞」，不是「一个」。 数据仍是 §3 · 一 那组 x = [3,1,4,1,5,9,2,6]，每个 lane 初始持有 (x, 1)。 off=4 那一轮，lane 0 的伙伴 lane 4 递来的是它自己的 (5, 1.000)； 但到 off=2 那一轮，lane 2 递来的 (4, 1.135) 已经是 lane 2 和 lane 6 合并后的结果。 信息就是这样每轮翻一倍：1 → 2 → 4 → 8。真实 warp 里 1 → 2 → 4 → 8 → 16 → 32，正好 5 轮。

两个顺带的问题

为什么不干脆先 warpReduceMax 求出全局 max，再 warpReduceSum？ 那样也对，而且 __expf 只要算 1 次（融合版要算 10 次）。 但那是两个前后依赖的归约，关键路径 5 + 5 = 10 步； 融合版每轮的两条 shuffle 互不依赖、可以背靠背发射，关键路径只有 5 步。 何况这是个访存瓶颈的 kernel，exp 根本不是成本所在。

更要紧的理由：这个合并运算必须能「两两合并」。 FlashAttention 分块算 softmax 时， 块是一块一块来的，根本拿不到全局 max —— 只能每块算出自己的 (m, s) 再两两合并。 这里写成融合形式，就是把它和 §5 · 三 要证结合律的那个 ⊕ 统一成同一个算子。

一个会让整行变成 NaN 的坑

幺元不能写 -INFINITY。

m = -INFINITY, s = 0        // 没分到元素的线程
m_n = max(-inf, -inf) = -inf
m - m_n = (-inf) - (-inf) = NaN
s = 0 × NaN + 0 × NaN = NaN   // 然后 NaN 顺着归约树污染整行

// 换成 -FLT_MAX：
m - m_n = (-FLT_MAX) - (-FLT_MAX) = 0
s = 0 × exp(0) + 0 × exp(0) = 0   // 安全退化

什么时候会有线程分不到元素？ N 不是 BLOCK 的整数倍时的最后一轮， 以及 N < BLOCK 的情况（比如 ./fused_ops s3 64 1000 3）。 所以脚本里专门有一条 N=1000 的边界测试。

换个角度：同一份代码，不同的层面

CUDA 最别扭的一点是：你写的是一个线程的代码，跑起来却是 256 个线程同时在跑同一份。 所以读这三个函数，光看「它算什么」不够，还得随时问一句 「这一句是作用在哪个层面上的」—— 是每个线程各管各的，还是一个 warp 32 个人一起， 还是整个 block 256 个人一起。

图 13 · 三层作用域，三种通信手段。 __shared__ 和 __syncthreads() 都在中间那个框上 —— 它们是 block 级的：每个 block 拿到自己独立的一份 smem， 屏障也只管住自己 block 里那 256 个线程。 往里，warp 内部根本用不着它们（shuffle 直接读寄存器）； 往外，block 之间压根没有这种东西 —— 这正是 N1 必须拆成两个 kernel 的原因。

if (threadIdx.x == 0) 不是「汇总」，是「选代表」

汇总在它之前就已经做完了 —— blockReduceSum 返回时， 256 个线程每一个手里都握着完整的 Σx²。 那为什么还要加这个 if？ 因为接下来要往显存写 rstd[row]，那是一个地址、一个 float。 256 个线程都去写会得到 256 次冗余写（值一样，不会错，但纯属浪费）。

所以它是并行编程里一个固定套路： 归约负责「算出来」，选代表负责「落笔」，两件事分开。 同样的套路在 blockReduceSum 里出现了两次： if (lane == 0) smem[warp] = v; 是每个 warp 选一个代表交作业， if (threadIdx.x == 0) smem[0] = v; 是全 block 选一个代表。

选几个代表？—— lane == 0 和 threadIdx.x == 0 不是一回事

这是读这段代码时最容易看错的地方。 threadIdx.x 是整个 block 内的编号（0…255）， 而 lane 是每个 warp 内的编号（0…31，每个 warp 都从 0 重新数）。 两者是这么拆出来的： 

const int lane = threadIdx.x & 31;   // 低 5 位 → 在本 warp 里排第几  0…31
const int warp = threadIdx.x >> 5;   // 高位   → 是第几个 warp      0…7

图 15 · 同样长得像「选 0 号」，选出来的人数差 8 倍。 lane == 0 在每个 warp 里都有一个，共 8 个线程 —— 但它们写的是 smem[warp]，8 个不同的下标，所以并不冲突。 threadIdx.x == 0 在整个 block 里只有一个，所以 smem[0] = v 只被一个线程执行。

smem[0] 被写了两次，为什么安全

它先在 ② 存过 warp 0 的部分和，又在 ⑥ 被覆写成全 block 的和。 关键在于「读」一定发生在「覆写」之前：

④ 那一行 v = (threadIdx.x < 8) ? smem[lane] : 0.0f; 里， 真正读 shared 的只有线程 0–7（其余直接拿幺元 0.0f），而这 8 个线程全在 warp 0 里； ⑤ 的 warpReduceSum 用的是全掩码 shuffle，会把 warp 0 的 32 个 lane 同步一次 —— 所以读必然完成在覆写之前。warp 1–7 从头到尾没碰 smem[0]，它们要到 ⑦ 之后才读。 两个 __syncthreads() 各挡一头：③ 挡在「写 8 个部分和」与「读它们」之间， ⑦ 挡在「覆写全和」与「全员读走」之间。

顺带一个隐含前提：④ 那行假定 warp 数 ≤ 32， 这样 ⑤ 一个 warp 就能把它们收完。BLOCK = 256 只有 8 个 warp， 而 CUDA 本来就限制一个 block 最多 1024 线程（= 32 个 warp）， 所以这个前提永远成立。

与之相对：屏障绝不能放进分支

「选代表」可以写在 if 里， __syncthreads() 绝对不行。 屏障要求 block 里每一个线程都到达； 少一个没到就是未定义行为 —— 可能挂死，也可能结果悄悄偏一点。 所以代码里两次 __syncthreads() 都写在 if 外面， 而 if (lane == 0)、if (warp == 0) 里头一个屏障都没有。 哪天想把它「优化」进 if (warp == 0) { … } 里，就炸了。

两个容易忽略的细节

① smem 为什么要当参数传进去？ __shared__ float smem[BLOCK/32] 是在 kernel 里声明的， 归约函数只是借用它。这样写 blockReduceSum 才能被四级台阶反复调用， 而由调用方决定这块 shared 什么时候分配、给谁用。

② pass1 里那次广播其实白做了。 blockReduceSum 结尾的 smem[0] → __syncthreads() → 全员读走，是为了让 256 个线程都拿到结果； 可 pass1 只有 thread 0 要用。 这是共用同一个 helper 的代价 —— 真正需要全员拿到结果的是 N2/N3/N4，那里每个线程都要拿 r 去缩放自己手上的元素。 量级上完全可以忽略（相对一行 14 KB 的显存流量）， 但它正好解释了为什么第 10 章 R6 只用一次 __syncthreads()。

两趟之间靠 dm 接力

pass1 里只有 thread 0 写 dm[row]； pass2 里 256 个线程读同一个地址 dm[row]，硬件广播一次就够。 整笔账对得上：读 x 两次 + 写 y 一次 = 12N × M = 168 MB， 加上 dm 往返的 32 KB（占 0.02%，可忽略）。

为了能一口气读完，下面把 §3 那两块归约积木、两个 kernel、以及怎么调一次贴全。 四级台阶共用同一份 blockReduceSum，后面 N2/N3/N4 就不再重复贴了。 完整文件见 §8 · 二。 

// ═══ 积木：warp 内 + 跨 warp 的两段式求和（§3 · 一、二）══════════════════
static const int BLOCK = 256;                  // 8 个 warp

__inline__ __device__ float warpReduceSum(float v) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v += __shfl_xor_sync(0xffffffffu, v, off);   // 蝶形，5 轮后全员持有全和
    return v;
}

__inline__ __device__ float blockReduceSum(float v, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    v = warpReduceSum(v);                      // ① 每个 warp 各归各的
    if (lane == 0) smem[warp] = v;             // ② 8 个结果落进 shared
    __syncthreads();                           // ③ 等 8 个都写完
    v = (threadIdx.x < (BLOCK >> 5)) ? smem[lane] : 0.0f;  // 加法的幺元
    if (warp == 0) v = warpReduceSum(v);       // ④ 0 号 warp 把 8 个归成 1 个
    if (threadIdx.x == 0) smem[0] = v;         // ⑤ 放回 shared
    __syncthreads();                           // ⑥ 等它写完
    return smem[0];                            // ⑦ 全 block 一起读走
}

// ═══ N1 第一趟：只算每行的 rstd，写进一个长度 M 的小数组 ══════════════════
__global__ void rms_n1_pass1(const float *__restrict__ x, float *__restrict__ rstd,
                             int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;          // 一个 block 负责一行
    const float *xr = x + row * (long long)N;  // (long long) 防 M·N 溢出 int

    float acc = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) {   // 跨步循环，天然合并
        float v = xr[i];
        acc += v * v;
    }
    acc = blockReduceSum(acc, smem);
    if (threadIdx.x == 0)
        rstd[row] = rsqrtf(acc / N + eps);     // rsqrtf 是硬件指令，一条搞定
}

// ═══ N1 第二趟：把 x 再读一遍，乘上 rstd 和权重，写出去 ═══════════════════
__global__ void rms_n1_pass2(const float *__restrict__ x, const float *__restrict__ w,
                             const float *__restrict__ rstd, float *__restrict__ y, int N) {
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;
    const float r = rstd[row];                 // 整个 block 读同一个地址 → 广播
    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = xr[i] * r * w[i];               // ← 第二次读 x，12N 的根源
}

// ═══ 怎么调 ═════════════════════════════════════════════════════════════
// 显存四块：dx / dy 各 M×N 个 float；dw 长度 N（权重）；
//          dm 长度 M —— 就是 rstd，两趟之间靠它传值
CUDA_CHECK(cudaMalloc(&dm, M * sizeof(float)));

// grid = M（行数，一个 block 一行），block = BLOCK = 256
// 全文里这两行在 launch 那个 lambda 的 switch (kind) 的 case K_N1 分支下
// 两个 kernel 都不需要动态 shared，所以 <<<>>> 里只写两个参数
rms_n1_pass1<<<M, BLOCK>>>(dx, dm, N, eps);           // 读 x        → 写 rstd
rms_n1_pass2<<<M, BLOCK>>>(dx, dw, dm, dy, N);        // 读 x+rstd+w → 写 y

// 注意：两次发射之间不用写任何同步。同一个 stream 上，后发的 kernel
// 一定在前一个完全结束之后才开始 —— pass2 读到的 rstd 必然是全的。

代码里那两个关键字

__inline__ 就是 C++ inline 的 GNU / CUDA 拼法，nvcc 预定义了它 —— 不是什么 CUDA 特有的加速开关。这里写它基本是习惯写法， 有三处容易误解：

__inline__ 到底做了什么
常见误解实际
inline = 一定内联 inline 在 C++ 里是链接性关键字；要不要真内联，编译器自己决定
写它是为了消掉调用开销 __device__ 函数 nvcc 默认就几乎总是内联 （除非递归、通过函数指针调用、或标了 __noinline__），写不写一样
不写会出错 单文件编译不会。它真正必要的场合是放在头文件里被多个 .cu 包含 —— 那时需要 inline 链接性来避免 multiple definition

想真正表态，关键字是 __forceinline__（强制） 和 __noinline__（禁止）。

不过「真的被内联」这件事，到 N3 就性命攸关了

N3 把整行 32 个 float 存进 xs[MAXS]，必须待在寄存器里。 如果 blockReduceSum 真以函数调用的形式存在， 寄存器分配就得跨调用点保活 xs[]，很可能被迫 spill 进 local memory（也就是显存）， 「数据留在片上」的前提当场作废。 所以这里要的是真内联 —— 但功劳属于 nvcc 对 __device__ 的默认行为，不是这个关键字；真要钉死该写 __forceinline__。

__restrict__：一个你对编译器的承诺

它是 C99 restrict 的 C++ 写法 （C++ 标准没有 restrict，各家用 __restrict__ 扩展）。 含义：在这个指针的作用域内，它指向的内存只会通过它访问，不会和别的指针重叠。

图 16 · __restrict__ 让编译器敢做的事。 没有它，编译器必须假设 yr[i] = xr[i] * r * w[i] 里那个写可能改到 xr 或 w （毕竟都是 float*），于是每轮都得重新 load，也不敢走只读缓存。 这份代码里 dx / dy 是两次独立的 cudaMalloc，承诺成立。

const 和 __restrict__ 是一对，缺一不可。 nvcc 只有在能证明「这块数据在整个 kernel 执行期间只读」时， 才会生成走只读数据缓存的 load（LDG.E.CI，也就是 __ldg() 那条路径，sm_35 起）： const 说「我不写它」，__restrict__ 说「别人也不会通过别名写它」—— 两句话凑齐，编译器才敢用那条路径。 

const float *__restrict__ x    // __restrict__ 在 * 右边 → 修饰指针本身
                               // const 在 * 左边       → 修饰指向的数据
float *const x                 // 这才是「指针本身不可改」，完全两码事

怎么自己验

仓库里的 check_sass.sh 支持换二进制： BIN=./fused_ops bash check_sass.sh。 然后在反汇编里对比 LDG.E.CI（走只读缓存） 和 LDG.E（普通 global load）的条数；把 __restrict__ 去掉重编一遍再数一次。 这正是这个系列一贯的「条数账」做法 —— 和 N3→N4 的 float4 属于同一类改动：字节数不变，只动指令条数。

一个 block 一行，合适吗

N=3584，BLOCK=256 → 每个线程负责 14 个元素，循环 14 轮。 行数 M 就是 grid 大小。M=8192 时有 8192 个 block 排队， 128 个 SM 轮着跑，填得很满。 但 decode batch=1 时 M=1 —— 整张卡只有一个 block 在干活，127 个 SM 在看戏。 这就是 §7 形状扫描要测的东西。

二、N2：融成一个 kernel，字节数一个都没省↑

__global__ void rms_n2(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    float acc = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) {
        float v = xr[i];                       // ← 第一次读
        acc += v * v;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = xr[i] * r * w[i];             // ← 第二次读，同样的地址
}

// ═══ 怎么调：和 N1 的唯一区别是只发一次 ═════════════════════════════════
rms_n2<<<M, BLOCK>>>(dx, dw, dy, N, eps);              // 读 x 两次 → 写 y

// 参数表里没有 dm 了 —— 不再需要那个长度 M 的中间数组，也省掉一次 kernel launch。
// 但 x 仍然从显存读了两遍，字节数一个都没省，还是 12N。

图 17 · N2 拿掉的是中间那个小方块，不是两头的读写。 rstd 从「显存里一个长度 M 的数组」变成「寄存器里一个 float r」， 少了一次 launch、少了 dm[] 的往返。 可 xr[i] 仍然出现了两次 —— 第一遍算平方和、第二遍算输出， 同一个地址从显存读了两遍。字节账里的大头一分没动。

那 N2 到底省了什么

省了三样，都很小： ① 一次 kernel launch（几微秒，而且对 M=8192 来说分摊到每行几乎为零）； ② rstd 数组的一写一读（4M 字节，相对 12NM 是万分之一）； ③ 第二趟不用再等第一趟整个 grid 结束（两个 kernel 之间有隐式同步）。

③ 其实是唯一可能有点量的一项， 但它也只在 M 小、grid 填不满时才明显。 预测：M=8192 时 N2 相对 N1 的提速在 1.00×–1.05× 之间。

跑完之后：这条预测错了，而且错得很有价值

实测 N2 相对 N1 是 1.49×， 不是 1.00×–1.05×。 上面那张表没算错 —— xr[i] 确实出现了两次， 访存指令确实发了 12N 字节。 错的是把「指令发出的字节」当成了「DRAM 搬运的字节」。

第二次读和第一次读之间，这个 block 只走了自己这一行 —— 14 KB，稳稳躺在 L2 里。反推下来 N2 真正搬的是 8.1N，和 N3 的 8.0N 几乎一样， 所以耗时也几乎一样（0.2591 ms vs 0.2560 ms）。 完整的追查过程见 §9 · 三。 读到这里先别急着改上面的账 —— §7 的预测要保持原样，这是这套方法的规矩。

三、N3：把 x 留在寄存器 —— 这一级才动字节账↑

// 每线程最多存多少个 float。32 个 float = 32 个寄存器，离 255 的上限还远，不会 spill。
static const int MAXS = 32;                    // 单行最长 = BLOCK × MAXS = 8192

__global__ void rms_n3(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    float xs[MAXS];                            // 本线程负责的元素，全放寄存器
    float acc = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {           // ← 固定次数，常量下标
        int i = threadIdx.x + c * BLOCK;
        float v = (i < N) ? xr[i] : 0.0f;      // 越界喂 0，不影响平方和
        xs[c] = v;
        acc += v * v;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i < N) yr[i] = xs[c] * r * w[i];   // ← 直接用寄存器，不回显存
    }
}

// ═══ 怎么调：发射方式和 N2 一模一样 ═════════════════════════════════════
rms_n3<<<M, BLOCK>>>(dx, dw, dy, N, eps);              // 读 x 一次 → 写 y

// 但多了一个前提，必须在 host 侧先查 —— 整行得塞得进寄存器：
const bool needReg = (kind == K_N3 || kind == K_N4 || kind == K_S3 || kind == K_S4);
if (needReg && N > BLOCK * MAXS) {                 // 8192
    printf("✗ 这一级把整行存在寄存器里，单行最长 %d，而 N=%d。\n",
           BLOCK * MAXS, N);
    return 3;                                  // 不是实现偷懒，是硬件约束（§7·三）
}

图 18 · N3 改的不是算法，是数据住在哪里。 N2 里第一遍读进来的 v 用完就丢，所以第二遍只能回显存拿； N3 把整行摊在 xs[MAXS] 上一直留着，归约完直接拿寄存器里的值算输出。 这是四级台阶里唯一真正改变字节数的一步（12N → 8N，理论 1.5×）。 下半张是它的前提 —— 只要下标不是编译期常量，xs 就进不了寄存器，整级白做。

这里有个会让整级失效、而且从耗时上看不出原因的坑

循环必须写成"固定 MAXS 次 + 边界判断"，不能写成跨步循环配 xs[cnt++]。

// 错的写法（看起来更自然，但会毁掉这一级）
int cnt = 0;
for (int i = threadIdx.x; i < N; i += BLOCK) {
    xs[cnt++] = xr[i];                     // 下标是运行期算出来的
    ...
}

// 对的写法
#pragma unroll
for (int c = 0; c < MAXS; ++c) {              // 展开后 xs[0] xs[1] … 全是常量下标
    int i = threadIdx.x + c * BLOCK;
    ...
}

原因：GPU 的寄存器不能动态寻址。 下标只要不是编译期常量，编译器就没法把 xs 放进寄存器， 只好把它塞进 local memory —— 而 local memory 物理上就在显存里。

后果：x 还是被读了两次， 只不过第二次是从 local memory 读的。字节数一点没省，1.5× 不会出现， 而你从耗时上完全看不出是为什么。 唯一的线索在 ptxas -v 的输出里：N bytes spill stores。 这就是 run_fused.sh 第 0 步要死盯 spill 的原因。

代价是单行长度被卡死：N ≤ BLOCK × MAXS = 256 × 32 = 8192。 超过就放不下。程序会直接拒绝并说明原因，而不是偷偷 spill。 这个约束不是实现偷懒 —— 它和 FlashAttention 必须分块是同一个物理限制，§5 · 五 细说。

四、N4：float4，字节不变，只动条数↑

// float4 版：8 个 float4 也是 32 个 float。两条路径的寄存器压力刻意做成一样，
// 这样 N3→N4 就是干净的单变量对照 —— 只动指令条数，不动寄存器。
static const int MAXV = 8;                     // MAXV × 4 = MAXS = 32

__global__ void rms_n4(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const int n4 = N >> 2;                        // 一行有多少个 float4

    // reinterpret_cast 把 float* 重新解释成 float4*，地址必须 16 字节对齐 ——
    // cudaMalloc 返回的指针是 256 字节对齐的，而 row*N 只要 N%4==0 就仍然对齐。
    const float4 *xr = reinterpret_cast<const float4 *>(x + row * (long long)N);
    float4       *yr = reinterpret_cast<float4 *>(y + row * (long long)N);
    const float4 *wr = reinterpret_cast<const float4 *>(w);

    float4 xs[MAXV];                           // 8 个 float4 = 32 个寄存器，和 N3 一样
    float acc = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        float4 v = (i < n4) ? xr[i] : make_float4(0.f, 0.f, 0.f, 0.f);
        xs[c] = v;
        acc += v.x * v.x + v.y * v.y + v.z * v.z + v.w * v.w;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) continue;
        float4 v = xs[c], g = wr[i], o;        // 权重也按 float4 读
        o.x = v.x * r * g.x;  o.y = v.y * r * g.y;
        o.z = v.z * r * g.z;  o.w = v.w * r * g.w;
        yr[i] = o;                             // 一条 STG.128 写回 4 个 float
    }
}

// ═══ 怎么调：和 N3 一字不差 ═════════════════════════════════════════════
rms_n4<<<M, BLOCK>>>(dx, dw, dy, N, eps);              // 读 x 一次 → 写 y

// 除了 N3 那条寄存器长度的守卫，还多一条对齐守卫：
const bool needVec4 = (kind == K_N4 || kind == K_S4);
if (needVec4 && (N & 3)) {                          // N 不是 4 的倍数
    printf("✗ float4 版要求 N 是 4 的倍数（当前 N=%d）\n", N);
    return 3;
}

图 19 · 搬的字节一个不多不少，发的指令少了 3/4。 两边都是完全合并的访存 —— 每字节的效率一样， 差别只在「同样多的字节，用几条指令搬完」。 所以字节账纹丝不动（还是 8N），能不能变快要看另一本账： 访存指令的发射是不是已经成了瓶颈。如果 N3 的 MBU 已经很高，说明瓶颈在带宽不在指令， N4 就不会有提升 —— 这本身就是个判据。

两个读入循环到底差在哪

两边的 int i = threadIdx.x + c * BLOCK; 一字不差 —— 可 N3 里 i 是「第几个 float」， N4 里是「第几个 float4」。 这是全部差异的源头，其余几处都是被它带出来的。

图 20 · 同一个 c，N4 扫过的范围是 N3 的 4 倍。 所以轮数从 14 降到 4。两边都是完全连续的访存，谁也不比谁更「合并」—— 区别只在一条指令覆盖多宽。 下半张最能说明问题：c = 1 时同一个 i = 0 + 1×256，N3 落在 float #256，N4 落在 float #1024。

一个容易忽略的不对称

N3 里 3584 ÷ 256 = 14 正好整除，每个线程都取 14 个 float。 N4 里 n4 = 896，而 896 ÷ 256 = 3.5 —— 线程 0–127 取 4 个 float4（16 个 float）， 线程 128–255 只取 3 个（12 个 float）。 128×16 + 128×12 = 3584 ✓ 总数对得上，只是负载不再均匀。 差半轮，对这个访存瓶颈的 kernel 可以忽略； 但它解释了 MAXV = 8 为什么要留一倍余量 —— 3.5 轮向上取整才 4， 剩下的冗余是留给更长的行的。

MAXV = 8 是故意选的：8 个 float4 = 32 个 float，和 N3 的 MAXS = 32 完全相同。 两条路径的寄存器压力做成一样， N3→N4 才是干净的单变量对照 —— 只动指令宽度，不动寄存器数。

对齐要求，以及为什么这里是安全的

float4 访存要求地址 16 字节对齐。 cudaMalloc 返回的指针是 256 字节对齐的； 行首地址是 base + row·N·4，只要 N % 4 == 0 就仍然 16 字节对齐。 程序在启动前会检查 N 是不是 4 的倍数，不是就拒绝跑。 3584 % 4 == 0 ✓，2048 % 4 == 0 ✓。

预测：N4 相对 N3 大约 1.0×–1.15×。 字节数完全没变，理论上不该快。能快一点的话， 来自更少的访存指令和更少的内存请求（4 条 32 位并成 1 条 128 位）， 也就是 SGEMM 那边的"条数账"和"请求账"。 但这两本账只有在带宽没跑满时才有空间 —— 如果 N3 的 MBU 已经很高，N4 应该几乎没有提升。这一条本身就是个判据。

一、为什么要减 max↑

softmax(x)_i = exp(x_i) / Σ_j exp(x_j)       // 教科书定义

直接照着算会溢出。 fp32 能表示的最大值约 3.4×10³⁸，而 exp(89) 就超了。 注意力打分经过 1/√d 缩放后通常在 ±20 以内，但训练不稳或长上下文时冲到 90 以上完全可能， 一旦溢出就是 inf / inf = NaN。 

softmax(x)_i = exp(x_i − m) / Σ_j exp(x_j − m)    // m = max(x)，恒等变形

// 为什么相等：分子分母同乘 exp(−m)，约掉了
// 为什么安全：x_i − m ≤ 0，所以 exp(·) ∈ (0, 1]，永远不会溢出

代价就是那一趟。 要减 max，就得先知道 max； 要知道 max，就得把整行看完 —— 于是朴素实现必须扫三趟。

二、递推式怎么来的↑

换个想法：如果我不等看完整行，而是边扫边维护一对 (m, s) 呢？ 约定 m_k 是前 k 个元素的最大值， s_k = Σ_{j≤k} exp(x_j − m_k) 是以当前最大值为基准的部分和。

现在来了第 k+1 个元素 x。新的最大值是 m' = max(m_k, x)。 问题是 s_k 用的基准是旧的 m_k，基准变了，它就不能直接加。

先把两个记号分清楚 —— 同一批数 x_1 … x_k，用不同基准记账，得到的是不同的数： 

s_k      = Σ_{j≤k} exp(x_j − m_k)      // 手里已经有的，旧基准 m_k
s_k(m')  = Σ_{j≤k} exp(x_j − m')       // 想要的，新基准 m'

两者只差一个常数倍 —— 下面五步就是把这个倍数找出来。 

// ① 在指数里加个零（−m' + m'），什么都没改变
    x_j − m_k  =  x_j − m' + m' − m_k

// ② 重新分组：一半随 j 变，一半是常数
               =  (x_j − m')  +  (m' − m_k)
                  └ 随 j 变 ┘     └ 与 j 无关 ┘

// ③ 用 exp(a + b) = exp(a) · exp(b) 拆开
    exp(x_j − m_k)  =  exp(x_j − m') · exp(m' − m_k)

// ④ 对 j 求和 —— 常数可以提到求和号外面
    s_k  =  Σ_{j≤k} exp(x_j − m_k)
         =  Σ_{j≤k} [ exp(x_j − m') · exp(m' − m_k) ]
         =  exp(m' − m_k) · Σ_{j≤k} exp(x_j − m')
            └ 提出来的公因子 ┘     └──── 这就是 s_k(m') ────┘
         =  exp(m' − m_k) · s_k(m')

// ⑤ 反解出我们真正想要的 s_k(m')：两边同除 exp(m' − m_k)
    s_k(m')  =  s_k / exp(m' − m_k)
             =  s_k · exp(m_k − m')       // ← 指数反号了！
                      ↑ 这才是代码里那个缩放因子

第 ⑤ 步是最容易卡住的地方

④ 里提出来的公因子是 exp(m′ − m_k)， 而代码里用的是 exp(m_k − m′) —— 两者指数正好相反。 不矛盾：④ 是「把新账乘成旧账」，⑤ 是「把旧账除成新账」， 除以 exp(m′ − m_k) 就等于乘以 exp(m_k − m′)。 而我们手里有的是旧账 s_k、要的是新账，所以代码里出现的一定是 exp(m_k − m′)，且因为 m′ ≥ m_k，它恒 ≤ 1。

拿 x = [1, 2]、旧基准 m_k = 2、新基准 m′ = 5 验一遍
量怎么算值
旧账 s_kexp(1−2) + exp(2−2) 1.367879
缩放因子exp(m_k − m′) = exp(−3) 0.049787

图 21 · 基准只是记账单位，量本身没变。 同一批数的「真实和」T 是固定的；s 不过是把它乘上 exp(−基准) 缩到安全范围里。 换基准 = 换这个乘数，比例自然是两个 exp 之商。 T 只是想清楚问题用的中间量 —— 代码里绝不能真去算，那正是 §5 · 三 证结合律时要再用一次的同一个技巧。

把换算好的旧账，和本来就以 m′ 记账的新项加起来，就是那两行递推： 

m' = max(m_k, x)
s' = s_k · exp(m_k − m') + exp(x − m')
     └─── 旧账换算到新基准 ───┘   └─ 新项，本来就以 m' 记账 ─┘

就这两行。 直观理解：遇到更大的 max，就把已经累计的和按比例"缩"回去。 缩放因子 exp(m_k − m') 一定 ≤ 1，因为 m' ≥ m_k。 没遇到更大的 max 时，m' = m_k，因子是 exp(0) = 1，退化成普通累加。

图 22 · 「缩回去」是什么意思。 纵轴是每一项 exp(x_j − 基准) 的值，三块共用一把尺子（虚线是 1.0）。 扫到更大的元素 5 时，基准从 2 换成 5，所有旧项乘上同一个因子 exp(2−5) = 0.0498（②）， 然后新项 exp(5−5) = 1 才能安全地加进去（③）。 因子恒 ≤ 1，因为 m′ ≥ m；没遇到更大的 max 时因子是 exp(0) = 1，退化成普通累加。

省下来的是哪一趟

三、结合律：为什么能做树形归约↑

这是最容易被跳过、但绝不能跳过的一步

上面的递推是串行推出来的：一个一个往里加。 但 GPU 上我们要用蝶形归约，256 个线程两两合并、合并顺序和串行扫描完全不同。 凭什么结果还一样？ 因为这个合并运算满足结合律。不证明这一点，整个 kernel 的正确性就是悬空的。

先把合并运算写成一般形式（不再限定第二个操作数是单个元素）： 

(m₁, s₁) ⊕ (m₂, s₂) = ( max(m₁, m₂),
                         s₁·exp(m₁ − max) + s₂·exp(m₂ − max) )

先别急着看式子 —— 它到底在干什么

最要紧的一句：(m, s) 不是「两个数」，它是一整段数据的摘要。 一段数据 A = {x₁ … x_k} 可能有几千个数， 压成摘要就只剩两个 float：m = max(A)，s = Σ exp(x_j − m)。

而 ⊕ 回答的问题是： 已知 A 的摘要、B 的摘要，能不能直接算出 A∪B 的摘要 —— 不回头翻原始数据？ 能，公式就是它。

图 23 · 摘要能合并，所以原始数据可以扔掉。 这正是 warp 归约和 FlashAttention 共同依赖的性质： 32 个 lane 各自摘要自己那一摞，两两 ⊕ 就能得到全 warp 的摘要， lane 之间传的是 2 个 float 而不是几千个； FlashAttention 的每个分块算完摘要就把分块丢掉，块与块之间也靠 ⊕。

回头看式子，两个分量各说一句就够了。 先给那个反复出现的量起个名 —— 式子里 max 出现三次， 指的都是同一个数： 

令 m = max(m₁, m₂)

(m₁,s₁) ⊕ (m₂,s₂) = (  m  ,  s₁·exp(m₁−m) + s₂·exp(m₂−m)  )
                       ↑              ↑                  ↑
                  合并后的最大值   A 的账换到新基准    B 的账换到新基准

// 第一个分量：两堆数合起来的最大值，就是两个最大值里更大的那个 —— 显然
// 第二个分量：s₁ 以 m₁ 记账、s₂ 以 m₂ 记账，量纲不同不能直接加，
//             所以两边都先换算到新基准 m 再加（§5·二 那个换基准公式，这次两边都要换）

// 代进上面的例子：
exp(m₁ − m) = exp(2−5) = 0.0498      // m 小的那边，被缩下去
exp(m₂ − m) = exp(5−5) = 1.0000      // m 大的那边，因子恒为 1

两个因子里必有一个是 exp(0) = 1，另一个 ≤ 1 —— 所以这一步永远不会溢出。

和 §5 · 二 那个递推是什么关系

§5 · 二 的递推，就是 ⊕ 的一个特例。 单个元素 {x} 的摘要是什么？ m = max({x}) = x，s = exp(x − x) = 1 —— 也就是 (x, 1)。代进去：

(m_k, s_k) ⊕ (x, 1)
  = ( max(m_k, x),  s_k·exp(m_k−m′) + 1·exp(x−m′) )
  = ( m′,           s_k·exp(m_k−m′) + exp(x−m′)   )   // 和 §5·二 一字不差

那为什么还要写成一般形式？ 因为蝶形归约和分块合并时，第二个操作数不是一个元素，而是另一整段的摘要。 FlashAttention 尤其如此 —— 块是一块一块来的， 根本拿不到全局 max，只能拿摘要两两合并。

证法一：合出来的，就是并集的摘要

回头看 图 23 —— 它其实已经把结合律证掉了一大半。 图 23 说的就是一条引理： 两段各自的摘要合并起来，正好等于「这两段并在一起」那一整段的摘要。 把它当已知，剩下的只有三行： 

// 引理（就是图 23，直接代定义验算即可）
    摘要(A) ⊕ 摘要(B)  =  摘要(A ∪ B)

// 于是两种括号法分别是
    ( 摘要A ⊕ 摘要B ) ⊕ 摘要C  =  摘要(A∪B) ⊕ 摘要C  =  摘要( (A∪B) ∪ C )
    摘要A ⊕ ( 摘要B ⊕ 摘要C )  =  摘要A ⊕ 摘要(B∪C)  =  摘要( A ∪ (B∪C) )

// 而集合的并当然可结合
    (A∪B) ∪ C  =  A ∪ (B∪C)

// 两边摘要的输入是同一个集合，输出自然相同
    (摘要A ⊕ 摘要B) ⊕ 摘要C  =  摘要A ⊕ (摘要B ⊕ 摘要C)        // ∎

整个证明归结到「集合的并可结合」—— 这件事没人会怀疑。 一句话记住它： 不管你怎么加括号，合出来的都是「这几段并在一起」 那一整段的摘要；而并在一起，跟你怎么分组无关。

这个证法的适用范围 —— 以及为什么还有另一个

它只覆盖「确实是某个集合的摘要」的那些 (m, s)。 对 kernel 来说完全够用：每个 lane 一开始拿的就是自己那摞的摘要， 幺元 (−∞, 0) 是空集的摘要，合并出来的还是摘要 —— 永远跑不出这个范围。

下面折叠里那个证法对任意 (m, s) 都成立，代价是要多绕一圈。 它的真正价值不在这里，而在于：哪天你要并行归约别的东西 —— top-k、方差、logsumexp 的变体 —— 需要一套可靠办法判断「这个算子能不能乱序合并」， 「找一个到已知可结合结构的同态」就是那个通用办法。

证法二：把结合律从 (max, +) 搬过来 —— 更严密，也更通用选读

证明思路：给 (m, s) 换一套坐标 —— 换到一个不依赖基准的表示上去。 注意到对任意一段数据 A，无论用什么基准 m，量 

T(A) = s · exp(m) = Σ_{j∈A} exp(x_j)      // 真正的"无偏指数和"

都是同一个数——基准 m 只是为了防溢出而人为引入的，乘回去就消掉了。

先把要证的东西摆清楚

// 换坐标的映射
φ(m, s) = ( m , s·exp(m) ) = ( M , T )

// 新坐标里的运算：两个分量各管各的
(M₁, T₁) ⊞ (M₂, T₂) = ( max(M₁, M₂) , T₁ + T₂ )

// 要证：⊕ 可结合。路线四步 ——
①  φ 是单射                     // 能原路还回来
②  φ(A ⊕ B) = φ(A) ⊞ φ(B)       // φ 把 ⊕ 翻译成 ⊞
③  ⊞ 可结合                      // 显然，但要说
④  ①+②+③  ⟹  ⊕ 可结合

① φ 是单射 —— 这一步不能省

给定新坐标 (M, T)，可以唯一还原回去：
    m = M
    s = T · exp(−M)

所以   φ(m₁,s₁) = φ(m₂,s₂)  ⟹  (m₁,s₁) = (m₂,s₂)

为什么非要这一步

② 只能推出「两种括号法算出来的 T 相同」。 可我们真正要的是「两种括号法算出来的 (m, s) 相同」—— 这是代码里实际存的东西。 从「T 相同」跳到「(m,s) 相同」， 靠的正是 φ 可逆。 少了这句，证明链是断的。

② φ 把 ⊕ 翻译成 ⊞

令 m = max(m₁, m₂)。按 ⊕ 的定义
    A ⊕ B = ( m , s₁·exp(m₁−m) + s₂·exp(m₂−m) )

// 第一个分量
    M(A ⊕ B) = m = max(m₁, m₂) = max( M(A), M(B) )        // ⊞ 的第一分量 ✓

// 第二个分量 —— 关键是 m 会被完全消掉
    T(A ⊕ B) = [ s₁·exp(m₁−m) + s₂·exp(m₂−m) ] · exp(m)
             = s₁·exp(m₁−m)·exp(m) + s₂·exp(m₂−m)·exp(m)   // 乘进括号
             = s₁·exp(m₁−m+m)      + s₂·exp(m₂−m+m)        // exp(a)exp(b)=exp(a+b)
             = s₁·exp(m₁)          + s₂·exp(m₂)
             = T(A) + T(B)                                // ⊞ 的第二分量 ✓

⟹  φ(A ⊕ B) = φ(A) ⊞ φ(B)

注意第二个分量里 m 一进一出、被彻底消掉了 —— 这就是「T 不依赖基准」的全部含义。 换句话说：⊕ 看着复杂，是因为它在「带基准」的坐标里干活；换到 T 坐标，它就是一个普通加法。

③ ⊞ 可结合、可交换

⊞ 的两个分量互不干涉：第一个分量是 max，第二个是 +。 而 max 和 + 都既可结合又可交换，所以逐分量组合出来的 ⊞ 也是。 可交换这一条对蝶形同样要紧 —— 一对 lane 谁读谁、谁在左谁在右，结果不能变。

④ 拼起来

φ( (A⊕B) ⊕ C )  =  φ(A⊕B) ⊞ φ(C)          // 由 ②
                 =  ( φA ⊞ φB ) ⊞ φC        // 由 ②
                 =  φA ⊞ ( φB ⊞ φC )        // 由 ③ ← 唯一用到结合律的地方
                 =  φA ⊞ φ(B⊕C)             // 由 ②
                 =  φ( A ⊕ (B⊕C) )          // 由 ②

两端 φ 的值相同，而 φ 是单射（①），所以

    (A⊕B) ⊕ C  =  A ⊕ (B⊕C)                        // ∎

图 25 · 换坐标，是为了把难证的搬到好证的地方。 下面那层的结合律是白送的（max 和 + 谁都知道可结合）； 上面那层才是我们真正要的，但直接证很别扭。 φ 的作用就是在两层之间架桥 —— 横着走（先合并再换坐标）和绕着走（先换坐标再合并）结果一致， 桥又是双向的（可逆），于是下层的性质原样抬到上层。

幺元：为什么是 (−∞, 0)

取 e = (−∞, 0)，对应 T(e) = 0 —— 也就是空集。

验证 e ⊕ (m, s)：令 M = max(−∞, m) = m
    s′ = 0·exp(−∞ − m) + s·exp(m − m)
       = 0·0            + s·1
       = s
⟹  e ⊕ (m, s) = (m, s)   // 另一侧同理，交换律已证

数学上 −∞ 完美，浮点里却会炸： (−∞) − (−∞) = NaN。 所以代码里用 -FLT_MAX 顶替 —— 那个坑和修法见 §3 · 三。

拿三个单元素段验一遍：A=(1,1)、B=(2,1)、C=(5,1)
算法中间结果最终结果
先左后右(A⊕B)⊕C A⊕B = (2, 1.367879) (5, 1.068102707)
先右后左A⊕(B⊕C) B⊕C = (5, 1.049787) (5, 1.068102707)
两者之差 中间结果完全不同 0.0　逐位相同 ✓

顺带对一下 T：exp(1)+exp(2)+exp(5) = 158.520497， 而 1.068102707 × exp(5) = 158.520497 —— 两种括号法算出来的 (m, s) 还原出同一个 T，正是 ② 说的那件事。

结论

在 (max, T) 坐标下，⊕ 就是 「取最大值」和「求和」并排放着；这两个运算可结合可交换，幺元是 (−∞, 0)。 换句话说 (⊕, e) 构成一个可交换幺半群。 于是任意的合并顺序 —— 串行扫描、蝶形归约、 分块再合并 —— 结果完全一样。 而「分块再合并」这一条，正是 FlashAttention 的地基。

（T 只是证明用的中间量，代码里绝不能真的去算它 —— exp(m) 恰恰就是我们一开始要避免的那个溢出。 保持 (m, s) 的形式，是为了让每一步的中间值都留在安全区间里。）

四、数值上到底安不安全↑

表达式取值范围会不会出事
exp(x − m')(0, 1] 不会。x ≤ m' 恒成立
exp(m_k − m')(0, 1] 不会。m' ≥ m_k 恒成立
s[0, N] 不会。最多 N 个不超过 1 的数相加，N=152064 也远没到 fp32 上限
下溢exp(−100) ≈ 4e-44 会，但无害 变成 0，而它本来就该被忽略

唯一真正的风险是 s = 0 导致除零。 但 s 至少包含 exp(m − m) = 1 这一项 （最大的那个元素），所以 s ≥ 1，永远不会是 0。 前提是这一行至少有一个元素 —— 空行是调用方的错，kernel 不负责。

五、和 FlashAttention 的关系↑

把 §5 · 三 证明的结合律和 §4 · 三 那个"单行最长 8192"的约束放在一起看， FlashAttention 就是必然结果。

推理链说明
① 打分矩阵太大 上下文 4096、28 个头，一层就是 1.88 GB。写进显存再读出来，光这一项每层就要 7.46 ms
② 所以不能落 HBM 必须在 shared memory 里算完就消掉。而 shared 每 SM 只有 100 KB
③ 所以必须分块 一次只能处理一小块打分（比如 128×128），算完丢掉，再算下一块
④ 分块就要能合并 softmax 而 softmax 的分母是全行的和 —— 看不到全行怎么归一化？
⑤ online 递推给出了答案 每块算出自己的 (m, s)， 用 ⊕ 合并；结合律保证合并结果和"看完整行再算"完全一致

所以这份报告的 S3 注定要输，而这正是重点

S3 已经是"每个元素只过一次显存"的理论最优了（8N），但它仍然要把整个打分矩阵写出来再读回。

朴素三趟 S1     7.52 GB/层  →  7.46 ms  →  ×28 层 = 209 ms
本文最优 S3     3.76 GB/层  →  3.73 ms  →  ×28 层 = 104 ms
FlashAttention  0 GB        →  打分矩阵根本不存在

把 kernel 写快两倍，不如根本不写这个 kernel。 这是整份报告最该带走的一句话， 也是"算子级优化"和"算法级优化"的分水岭。 而你能跨过这条分水岭，靠的就是 §5 · 三 那半页证明。

阶梯二online softmax · 四级↑

和 RMSNorm 那条阶梯对称，但多一级台阶 —— 因为朴素版要三趟。

一、S1：三个 kernel，16N↑

和 N1 一个套路：趟与趟之间只能靠 kernel 边界同步， 中间结果落在长度 M 的小数组里。 只不过 softmax 要传两个中间量（max 和 sum）， 所以是三个 kernel、两个小数组。 

// ═══ 积木一：两个 warp 级归约，只差一个运算符 ═════════════════
__inline__ __device__ float warpReduceMax(float v) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v = fmaxf(v, __shfl_xor_sync(0xffffffffu, v, off));   // ← 取大
    return v;
}
__inline__ __device__ float warpReduceSum(float v) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v += __shfl_xor_sync(0xffffffffu, v, off);            // ← 求和，其余一模一样
    return v;
}

// ═══ 积木二：block 级求和 —— 结尾那三行是广播 ══════════════
__inline__ __device__ float blockReduceSum(float v, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    v = warpReduceSum(v);                      // ① 8 个 warp 并行各归各的
    if (lane == 0) smem[warp] = v;             // ② 每 warp 交一个
    __syncthreads();                           // ③ 等 8 个都写完
    v = (threadIdx.x < (BLOCK >> 5)) ? smem[lane] : 0.0f;  // 加法的幺元
    if (warp == 0) v = warpReduceSum(v);       // ④ warp 0 收尾
    if (threadIdx.x == 0) smem[0] = v;         // ⑤ ┐
    __syncthreads();                           // ⑥ ├ 广播给全 block
    return smem[0];                            // ⑦ ┘
}

// 注意：这份代码里没有 blockReduceMax —— 求 max 那边是直接写在 sm_s1_max 里的，
//       而且故意省掉了 ⑤⑥⑦，因为只有 thread 0 要用。下面对照着看。

// ═══ ① 求 max：整行扫一遍，每行吐出一个 float ═════════════════════════
__global__ void sm_s1_max(const float *__restrict__ x, float *__restrict__ mx, int N) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;

    float m = -FLT_MAX;                            // 求 max 的幺元（不能用 -INFINITY，§3·三）
    for (int i = threadIdx.x; i < N; i += BLOCK) m = fmaxf(m, xr[i]);

    // 两段式归约，但这里手写、没有广播尾巴 —— 只有 thread 0 要用结果
    const int lane = threadIdx.x & 31, warp = threadIdx.x >> 5;
    m = warpReduceMax(m);                      // warp 内，8 个 warp 并行
    if (lane == 0) smem[warp] = m;             // 每 warp 交一个
    __syncthreads();
    m = (threadIdx.x < BLOCK / 32) ? smem[lane] : -FLT_MAX;   // 其余 lane 喂幺元
    if (warp == 0) m = warpReduceMax(m);       // warp 0 收尾
    if (threadIdx.x == 0) mx[row] = m;         // 全 block 只落笔一次
}

// ═══ ② 求 exp 和：要用 ① 的 m，所以必须等 ① 整个 grid 跑完 ═══════
__global__ void sm_s1_sum(const float *__restrict__ x, const float *__restrict__ mx,
                          float *__restrict__ sm, int N) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    const float m = mx[row];                   // 256 个线程读同一个地址 → 广播

    float s = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK)
        s += __expf(xr[i] - m);                  // ← 第二遍读 x
    s = blockReduceSum(s, smem);               // 复用 §3 的 helper（带广播尾巴）
    if (threadIdx.x == 0) sm[row] = s;
}

// ═══ ③ 归一化：要用 ② 的 s ═══════════════════════════════════════════
__global__ void sm_s1_div(const float *__restrict__ x, const float *__restrict__ mx,
                          const float *__restrict__ sm, float *__restrict__ y, int N) {
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;
    const float m = mx[row], inv = 1.0f / sm[row];   // 先取倒数，循环里就不用除法

    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = __expf(xr[i] - m) * inv;           // ← 第三遍读 x；exp 又算了一遍
}

// ═══ 怎么调 ═════════════════════════════════════════════════════════════
// 两个长度 M 的小数组接力：dm 存每行的 max，ds 存每行的 Σexp
CUDA_CHECK(cudaMalloc(&dm, M * sizeof(float)));
CUDA_CHECK(cudaMalloc(&ds, M * sizeof(float)));

sm_s1_max<<<M, BLOCK>>>(dx, dm, N);                     // 读 x        → 写 dm
sm_s1_sum<<<M, BLOCK>>>(dx, dm, ds, N);                  // 读 x + dm   → 写 ds
sm_s1_div<<<M, BLOCK>>>(dx, dm, ds, dy, N);              // 读 x + dm+ds→ 写 y

// 三次发射之间不用写同步 —— 同一个 stream 上后发的 kernel
// 一定在前一个整个 grid 结束之后才开始。这正是趟与趟之间唯一的同步手段。

图 26 · 三个 kernel，两个小数组，三遍读 x。 dm 和 ds 的角色，就是 N1 里那个 dm —— 把中间结果甩到显存，只为了跨过 kernel 边界。 为什么非得跨？因为 ② 要用 ① 算出的 m， 而那是别的 block 算出来的；grid 这一层没有屏障（图 13）， 只能靠「下一次 kernel 发射」当同步点。

代码里两处值得留意的细节

① sm_s1_max 手写了归约，没有广播尾巴。 对比 sm_s1_sum 里直接调的 blockReduceSum —— 那个结尾有 smem[0] → __syncthreads() → 全员读走。 可这两个 kernel 都只有 thread 0 要用结果。 所以 ① 是「省对了」，② 是「为了复用 helper 多付了一点」 —— 正是 §4 · 一 那个观察的实例。

② __expf(xr[i] − m) 在 ② 和 ③ 各算了一遍。 同一个元素的 exp 算两次。放在「条数账」上是实打实的浪费， 但这个 kernel 是访存瓶颈 —— 字节账才是主角，所以这笔账在这里不疼。 而且 online 递推的 exp 只会更多不会更少 —— S1 每元素 2 次，S2 / S3 是 3 次。 它是拿算力换访存：16N → 8N，代价是多算一次 exp。详见 §6 · 三。

__expf 是硬件近似指令（对应 SASS 的 MUFU.EX2）， 比 expf 快一个量级，误差随 |x| 增大（NVIDIA 给的上界是 2 + floor(|1.16x|) ulp），在打分常见的 ±20 区间内约 1e-5 量级。 推理里普遍用它 —— softmax 的结果马上要做加权平均， 这点误差远小于 fp16 本身的表示误差。校验时容差要放宽到 2e-3。

二、S2：online 递推，省掉一趟↑

S2 省掉的是 S1 的第 ① 趟 —— 求 max 那一趟。 靠的不是代码技巧，是 §5 · 二 那个数学改写： online 递推让 max 和 sum 在同一趟里同时推进。 第三个 kernel 原封不动复用 S1 的，所以这一级只新写了一个 kernel。 

// ═══ 积木一：联合归约 —— warp 内把 (m, s) 当一个整体 ═════════════════
__inline__ __device__ void warpReduceMaxSum(float &m, float &s) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1) {
        float m_o = __shfl_xor_sync(0xffffffffu, m, off);   // 伙伴的 max
        float s_o = __shfl_xor_sync(0xffffffffu, s, off);   // 伙伴的 sum（每轮 2 条 shuffle）
        float m_n = fmaxf(m, m_o);                          // 新的公共基准
        s = s * __expf(m - m_n) + s_o * __expf(m_o - m_n);  // 两边都换算到 m_n 再加
        m = m_n;
    }
}

// ═══ 积木二：block 级联合归约 —— 两个分量一起收 ═══════════════════════
__inline__ __device__ void blockReduceMaxSum(float &m, float &s, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    const int nwarp = BLOCK >> 5;                           // = 8
    warpReduceMaxSum(m, s);                                 // ① 8 个 warp 并行各归各的
    if (lane == 0) { smem[warp] = m; smem[nwarp + warp] = s; }  // ② m 放前 8 格，s 放后 8 格
    __syncthreads();                                        // ③
    if (warp == 0) {
        // 幺元是 (-inf, 0)：最大值取 -inf 不影响 max，和取 0 不影响求和
        m = (lane < nwarp) ? smem[lane]         : -FLT_MAX;
        s = (lane < nwarp) ? smem[nwarp + lane] : 0.0f;
        warpReduceMaxSum(m, s);                             // ④ warp 0 收尾
        if (lane == 0) { smem[2 * nwarp] = m; smem[2 * nwarp + 1] = s; }   // ⑤ 存进最后 2 格
    }
    __syncthreads();                                        // ⑥ 注意：屏障在 if 外面
    m = smem[2 * nwarp];                                      // ⑦ ┐ 广播给全 block
    s = smem[2 * nwarp + 1];                                  //   ┘
}

// ═══ 一趟同时拿到 m 和 s ═════════════════════════════════════════════
__global__ void sm_s2_ms(const float *__restrict__ x, float *__restrict__ mx,
                         float *__restrict__ sm, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];              // 18 个 float
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;

    float m = -FLT_MAX, s = 0.0f;              // 幺元：空集的摘要
    for (int i = threadIdx.x; i < N; i += BLOCK) {
        float v = xr[i];                       // ← 整个 S2 只在这里读 x
        // 递推三行：见到更大的 max，就把已经累好的 s 按比例缩回去
        float m_n = fmaxf(m, v);
        s = s * __expf(m - m_n) + __expf(v - m_n);
        m = m_n;
    }
    blockReduceMaxSum(m, s, smem);             // 256 对 (m,s) 用 ⊕ 归成一对
    if (threadIdx.x == 0) { mx[row] = m; sm[row] = s; }     // 一次写两个小数组
}

// ═══ 第二个 kernel：原样复用 S1 的 sm_s1_div（再贴一遍，省得翻回去）═══
__global__ void sm_s1_div(const float *__restrict__ x, const float *__restrict__ mx,
                          const float *__restrict__ sm, float *__restrict__ y, int N) {
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;
    const float m = mx[row], inv = 1.0f / sm[row];   // 先取倒数，循环里不做除法

    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = __expf(xr[i] - m) * inv;           // ← 第二遍读 x
}

// ═══ 怎么调：只发两次 ═══════════════════════════════════════════════════
sm_s2_ms <<<M, BLOCK>>>(dx, dm, ds, N);                  // 读 x        → 写 dm + ds
sm_s1_div<<<M, BLOCK>>>(dx, dm, ds, dy, N);              // ← S1 的第三个 kernel，原样复用

// dm / ds 的分配和 S1 一模一样；少的只是一次 kernel 发射和一整趟读 x。

图 27 · 合并掉的是前两趟，第三趟原样保留。 S1 的 ① 和 ② 都要把整行读一遍，而它们做的事（求 max、求 exp 和）本来可以在一趟里同时推进 —— 这就是 online 递推买到的东西：16N → 12N，少一整趟读 x。 下半是联合归约的 shared 布局：前 8 格放各 warp 的 m， 接着 8 格放各 warp 的 s，最后 2 格存最终的 (m, s) 供全 block 读走 —— 比 blockReduceSum 多一倍多一点，因为要归约的是一对数。

三处值得留意

① 线程内是串行递推，线程间是树形归约 —— 两种顺序混在一起还能对。 每个线程在自己的跨步序列上一个一个往里加， 然后 256 对 (m, s) 两两合并。这一步的正确性完全依赖 §5 · 三 证的结合律 —— ⊕ 不在乎顺序。

② blockReduceMaxSum 每轮要 2 条 shuffle。 m 一条、s 一条，所以 5 轮共 10 条， 是 blockReduceSum 的两倍。但两条互不依赖、可以背靠背发射， 关键路径仍是 5 步（§3 · 三）。

③ 第 ⑥ 行那个 __syncthreads() 在 if (warp == 0) 外面。 和 blockReduceSum 一样的规矩： 「选代表」可以写在 if 里，屏障绝对不行。 挪进去就是未定义行为。

三、S3：一趟，8N↑

S3 把最后一趟也砍了：整行只过一次显存，(m, s) 全程待在片上。 代价是整行得塞进寄存器 —— 和 N3 同一个套路， 连「固定次数 + 常量下标」那条规矩都一样。 于是 dm / ds 两个中间数组彻底消失，只剩一个 kernel。 

// 每线程最多存多少个 float —— 和 N3 共用同一个常量
static const int MAXS = 32;                    // 单行最长 = BLOCK × MAXS = 8192

// 积木仍是 §6·二 那两个：warpReduceMaxSum / blockReduceMaxSum，原样复用
// 但这一级真的需要它结尾那几行广播 —— 256 个线程每人都要拿 (m,s) 去归一化自己手上的元素

// ═══ 一个 kernel 走完全程 ═══════════════════════════════════════════════
__global__ void sm_s3(const float *__restrict__ x, float *__restrict__ y, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    // 常量下标 + #pragma unroll，理由同 rms_n3（否则 xs 会被塞进 local memory）
    float xs[MAXS];                            // 整行摊在寄存器上
    float m = -FLT_MAX, s = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= N) { xs[c] = -FLT_MAX; continue; }  // 越界塞幺元，见下面的 callout
        float v = xr[i];                       // ← 整个 S3 只在这里读一次 x
        xs[c] = v;                             //   读完就留着，不再回显存
        float m_n = fmaxf(m, v);               // ┐
        s = s * __expf(m - m_n) + __expf(v - m_n);  // ├ 递推三行，同 S2
        m = m_n;                               // ┘
    }
    blockReduceMaxSum(m, s, smem);             // 256 对 (m,s) 归成一对，并广播给全员

    const float inv = 1.0f / s;                // 先取倒数，循环里不做除法
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i < N) yr[i] = __expf(xs[c] - m) * inv;   // ← 直接用寄存器，不回显存
    }
}

// ═══ 怎么调：只发一次，而且参数表里没有中间数组 ═════════════════════════
sm_s3<<<M, BLOCK>>>(dx, dy, N);                          // 读 x 一次 → 写 y

// 和 N3 共用同一条守卫 —— 整行得塞得进寄存器：
const bool needReg = (kind == K_N3 || kind == K_N4 || kind == K_S3 || kind == K_S4);
if (needReg && N > BLOCK * MAXS) {                 // 8192
    printf("✗ 这一级把整行存在寄存器里，单行最长 %d，而 N=%d。\n",
           BLOCK * MAXS, N);
    return 3;
}

图 28 · 三级砍下来：kernel 从 3 个到 1 个，中间数组从 2 个到 0 个。 dm / ds 之所以能消失，是因为它们本来只为「跨 kernel 边界」而存在； 当只剩一个 kernel，中间结果待在寄存器和 shared 里就够了。 下半是这笔买卖的另一面：exp 从每元素 2 次涨到 3 次 —— online 递推是拿算力换访存。在这个访存瓶颈的 kernel 里划算，换个场景未必。

越界位置为什么塞 -FLT_MAX 而不是 0

塞 0 的话，如果这一行的真实数据全是负数，这个假的 0 就会变成 max，整行结果全错。 塞 -FLT_MAX 则既不可能成为 max， exp(-FLT_MAX − m) 也是 0、对和没有贡献 —— 它就是 ⊕ 的幺元。

写回时还有 if (i < N) 兜底，这些位置根本不会被写出去。两道保险。 注意幺元是跟着运算走的： 求和用 0，求 max 用 -FLT_MAX，这里求的是 (max, sum) 这一对， 所以幺元是 (−∞, 0)。

到这一级，blockReduceMaxSum 的广播才终于没白做

S1 的 sm_s1_sum、S2 的 sm_s2_ms， 归约完都只有 thread 0 把结果写进小数组 —— 广播那几行是白搭的。 而 S3 里 256 个线程每一个都要拿 (m, s) 去归一化自己手上那十几个元素。 这也正是 §3 · 一 那句话的落点： 凡是「归约完所有线程都要用结果」的场合，才值得为广播付那一次 shared 往返。

四、S4：float4，顺便演示了分块合并↑

S4 = S3 + float4，字节数一个都没变（还是 8N），动的是访存指令条数。 但它顺手多做了一件事：因为一次进来 4 个元素， 它不得不先把这 4 个合成一个小块摘要，再并进累计值 —— 这就用上了 §5 · 三 那个一般形式的 ⊕， 而不是 S3 那个「并进一个元素」的特例。 

// float4 版：8 个 float4 也是 32 个 float，寄存器压力和 S3 刻意做成一样
static const int MAXV = 8;                     // MAXV × 4 = MAXS = 32

// 积木仍是 §6·二 那两个，原样复用；广播这一级同样真的需要

// ═══ 一个 kernel，一次搬 4 个 ═══════════════════════════════════════════
__global__ void sm_s4(const float *__restrict__ x, float *__restrict__ y, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];
    const long long row = blockIdx.x;
    const int n4 = N >> 2;                        // 一行有多少个 float4
    const float4 *xr = reinterpret_cast<const float4 *>(x + row * (long long)N);
    float4       *yr = reinterpret_cast<float4 *>(y + row * (long long)N);

    float4 xs[MAXV];                           // 8 个 float4 = 32 个寄存器
    float m = -FLT_MAX, s = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) { xs[c] = make_float4(-FLT_MAX, -FLT_MAX, -FLT_MAX, -FLT_MAX); continue; }
        float4 v = xr[i];                      // ← 一条 LDG.E.128，16 字节
        xs[c] = v;

        // 第 ① 层：先在寄存器里把这 4 个合成一个小块摘要 (mv, sv)
        float mv = fmaxf(fmaxf(v.x, v.y), fmaxf(v.z, v.w));
        float sv = __expf(v.x - mv) + __expf(v.y - mv) + __expf(v.z - mv) + __expf(v.w - mv);

        // 第 ② 层：再把这个小块用 ⊕ 并进累计值 —— 第二个操作数不再是单个元素
        float m_n = fmaxf(m, mv);
        s = s * __expf(m - m_n) + sv * __expf(mv - m_n);   // ← 注意 sv 前面这个系数
        m = m_n;
    }
    blockReduceMaxSum(m, s, smem);

    const float inv = 1.0f / s;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) continue;
        float4 v = xs[c], o;                   // 直接用寄存器里的 xs
        o.x = __expf(v.x - m) * inv;  o.y = __expf(v.y - m) * inv;
        o.z = __expf(v.z - m) * inv;  o.w = __expf(v.w - m) * inv;
        yr[i] = o;                             // 一条 STG.128 写回 4 个 float
    }
}

// ═══ 怎么调：和 S3 一字不差 ═════════════════════════════════════════════
sm_s4<<<M, BLOCK>>>(dx, dy, N);                          // 读 x 一次 → 写 y

// 除了 S3 那条寄存器长度守卫，还多一条对齐守卫：
const bool needVec4 = (kind == K_N4 || kind == K_S4);
if (needVec4 && (N & 3)) {                          // N 不是 4 的倍数
    printf("✗ float4 版要求 N 是 4 的倍数（当前 N=%d）\n", N);
    return 3;
}

三个「为什么」

为什么要减 mv？ 防溢出。v_i − mv ≤ 0 恒成立，每项都落在 (0, 1]。打分冲到 90 时 exp(90) = 1.22e39， 已经超过 fp32 上限 3.4e38；减掉 max 就永远不会。

为什么 sv 一定 ≥ 1？ 因为最大的那个分量贡献 exp(mv − mv) = 1。 所以 sv ∈ [1, 4] —— 四个数全相等时取 4，差距极大时趋近 1。 这也保证了后面 1.0f / s 不会除零。

为什么平铺写四项而不写循环？ float4 的四个分量是四个独立的寄存器，没有下标可循环 —— 展开写本来就是它的自然形态。

值得留意：块内用的是「朴素两趟」，不是递推

看清楚这两行的结构 —— 先求 max，再求和。这正是 S1 那套朴素做法， 而不是 online 递推。 

// 块内（4 个元素，全在寄存器里）：朴素两趟
mv = max(...)                    // 第 1 趟：求 max，0 次 exp
sv = Σ exp(v_i − mv)             // 第 2 趟：求和，4 次 exp        → 共 4 次

// 如果改成递推、逐个并进来：
for v_i in {x, y, z, w}:
    m_n = fmaxf(m, v_i);
    s = s * exp(m − m_n) + exp(v_i − m_n);   // 每元素 2 次 exp   → 共 8 次

4 次 vs 8 次 —— 朴素法在这里反而省一半。为什么？ 因为 S1 之所以被嫌弃，不是因为它算得多， 而是因为「两趟」意味着两遍过显存。 可这四个数就躺在寄存器里 —— 两趟不花钱， 于是朴素法「少算一半 exp」的优势就露出来了。

尺度数据在哪用什么exp 次数为什么这么选
块内4 个元素 寄存器 朴素两趟先 max 再求和 4 四个数同时在手，「两趟」不花钱
块与块之间8 轮循环 累计值在寄存器 online 递推 ⊕ 每块 2 块一个一个来，拿不到全局 max

FlashAttention 是同一个结构的放大版

tile 内部用朴素两趟（数据在 shared memory 里，扫两遍不碰显存）， tile 与 tile 之间用 ⊕。 和这里唯一的区别是块从 4 放大到 128×128、 摘要从寄存器挪到 shared。 「朴素」和「递推」不是谁取代谁 —— 是看数据能不能同时握在手里：握得住就朴素，握不住才递推。

图 29 · 这段代码已经是 FlashAttention 的最小形态了。 S3 往累计值里并的是一个元素 (v, 1)；S4 并的是一个小块的摘要 (mv, sv)。 块大小从 1 变成 4 —— 而 FlashAttention 做的事，就是把这个块从 4 放大到 128×128， 把摘要从寄存器挪到 shared memory。 合并公式一个字都不用改，因为 §5 · 三 证的就是任意两段摘要都能这么合。

图 30 · 省的不是元素项，是换基准。 每个元素总得算一次 exp，这部分谁也省不掉； 能省的只有「换基准」的开销 —— 逐元素做要换 B 次，分块做只换 1 次。 于是 逐元素 2B = B（元素项）+ B（换基准）， 分块 B+2 = B（元素项）+ 2（只换一次）。

B = 1 时分块反而更亏 —— 所以 S3 选逐元素不是疏忽

一个元素也要付那 2 次换基准的固定开销， B+2 = 3 反而比 2B = 2 多。 B = 2 打平，B ≥ 3 分块才开始赚。 每元素成本 (B+2)/B = 1 + 2/B，B 越大越逼近 1。

第三个参数那个 0

// 每个 block 固定 256 线程。一个 block 负责一行。
static const int BLOCK = 256;
// 寄存器驻留版每线程最多存多少个 float。32 个 float = 32 个寄存器，
// 加上其余开销还远没到 255 的上限，不会 spill。
// 于是单行最长 = BLOCK × MAXS = 256 × 32 = 8192。
static const int MAXS = 32;
// float4 版：8 个 float4 也是 32 个 float，两条路径的寄存器压力刻意做成一样，
// 这样 n3→n4 / s3→s4 就是干净的单变量对照（只动指令条数，不动寄存器）。
static const int MAXV = 8;

// ===========================================================================
//                            归约积木
// ===========================================================================
//
// 和第 10 章 R6 的区别，就一处，但很关键：
//
//   R6 用的是 __shfl_down_sync —— 归约结果只汇聚到 0 号 lane，因为那里只需要
//   一个线程把结果 atomicAdd 出去，其余线程的值是垃圾无所谓。
//
//   这里用 __shfl_xor_sync（蝶形/butterfly）—— 归约完【每个 lane 手里都是全和】。
//   因为接下来 32 个线程都要拿这个和去缩放自己负责的那几个元素，
//   少一个线程知道都不行。
//
//   代价是一样的：同样 5 轮，同样每轮一条 shuffle 指令。xor 版不多花钱，
//   只是把"漏斗"换成了"全交换"。
// ---------------------------------------------------------------------------
__inline__ __device__ float warpReduceSum(float v) {
    // off 依次取 16 8 4 2 1；lane ^ off 是"异或伙伴"，
    // 第 1 轮 0↔16、1↔17……第 5 轮 0↔1、2↔3……五轮之后所有 lane 都持有全和。
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v += __shfl_xor_sync(0xffffffffu, v, off);
    return v;
}

__inline__ __device__ float warpReduceMax(float v) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v = fmaxf(v, __shfl_xor_sync(0xffffffffu, v, off));
    return v;
}

// ---------------------------------------------------------------------------
// online softmax 的联合归约：把两个 (m, s) 合成一个
//
//   合并规则：
//       m = max(m1, m2)
//       s = s1·exp(m1 − m) + s2·exp(m2 − m)
//
//   为什么可以拿它做树形归约？因为这个运算【满足结合律】。
//   不满足的话，warp 内的蝶形归约就是错的 —— 它的合并顺序和串行扫描完全不同。
//   结合律的证明见导学 §5 · 三，一句话版本：
//   两个 (m,s) 合并后等价于"把两段数据拼起来重新算一遍 max 和 sum"，
//   而"拼起来"这个操作本身显然是可结合的。
// ---------------------------------------------------------------------------
// 注意这里【不能】用 -INFINITY 当初值。
//   没分到元素的线程 m 保持初值、s=0；两个这样的线程合并时
//   m - m_n = (-inf) - (-inf) = NaN，s = 0×NaN + 0×NaN = NaN，然后污染整行。
//   换成 -FLT_MAX：相减得 0，exp(0)=1，s = 0×1 + 0×1 = 0，安全退化。
__inline__ __device__ void warpReduceMaxSum(float &m, float &s) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1) {
        float m_o = __shfl_xor_sync(0xffffffffu, m, off);
        float s_o = __shfl_xor_sync(0xffffffffu, s, off);
        float m_n = fmaxf(m, m_o);
        // 两边都先缩放到新的 m_n 再相加。谁的 m 小，谁的 exp 就是个小于 1 的数，
        // 不会溢出；相等时两个 exp 都是 1，退化成普通求和。
        s = s * __expf(m - m_n) + s_o * __expf(m_o - m_n);
        m = m_n;
    }
}

// ---------------------------------------------------------------------------
// block 级归约：先 warp 内，再跨 warp。
//   BLOCK=256 → 8 个 warp。第一轮每个 warp 归出一个值放进 shared，
//   第二轮让 0 号 warp 把这 8 个值再归一次，最后广播给全 block。
// ---------------------------------------------------------------------------
__inline__ __device__ float blockReduceSum(float v, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    v = warpReduceSum(v);
    if (lane == 0) smem[warp] = v;
    __syncthreads();
    // 只有前 8 个 lane 有真值，其余喂 0（加法的幺元）
    v = (threadIdx.x < (BLOCK >> 5)) ? smem[lane] : 0.0f;
    if (warp == 0) v = warpReduceSum(v);
    // 0 号 warp 算完了，但全 block 都要用，所以再过一次 shared 广播
    if (threadIdx.x == 0) smem[0] = v;
    __syncthreads();
    return smem[0];
}

__inline__ __device__ void blockReduceMaxSum(float &m, float &s, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    const int nwarp = BLOCK >> 5;
    warpReduceMaxSum(m, s);
    if (lane == 0) { smem[warp] = m; smem[nwarp + warp] = s; }
    __syncthreads();
    if (warp == 0) {
        // 幺元是 (-inf, 0)：最大值取 -inf 不影响 max，和取 0 不影响求和
        m = (lane < nwarp) ? smem[lane]         : -FLT_MAX;
        s = (lane < nwarp) ? smem[nwarp + lane] : 0.0f;
        warpReduceMaxSum(m, s);
        if (lane == 0) { smem[2 * nwarp] = m; smem[2 * nwarp + 1] = s; }
    }
    __syncthreads();
    m = smem[2 * nwarp];
    s = smem[2 * nwarp + 1];
}

// ===========================================================================
//                            RMSNorm
//                y = x · rsqrt(mean(x²) + eps) · w
// ===========================================================================

// ---- N1：两趟，两个 kernel ------------------------------------------------
// 第一趟只算每行的 rstd，写进一个 M 长的小数组。
// 字节：读 x 一次 = 4N/行
__global__ void rms_n1_pass1(const float *__restrict__ x, float *__restrict__ rstd,
                             int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;

    float acc = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) {
        float v = xr[i];
        acc += v * v;
    }
    acc = blockReduceSum(acc, smem);
    if (threadIdx.x == 0)
        rstd[row] = rsqrtf(acc / N + eps);
}

// 第二趟再把 x 读一遍，乘上第一趟算好的 rstd 和权重，写出去。
// 字节：读 x 一次 + 写 y 一次 = 8N/行   （合计 12N）
__global__ void rms_n1_pass2(const float *__restrict__ x, const float *__restrict__ w,
                             const float *__restrict__ rstd, float *__restrict__ y, int N) {
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;
    const float r = rstd[row];
    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = xr[i] * r * w[i];
}

// ---- N2：融成一个 kernel，但 x 还是读两次 ---------------------------------
// 和 N1 的字节数【一模一样】。省掉的只有：一次 kernel launch、
// rstd 数组的一写一读（4M 字节，相对 12NM 可以忽略）。
// 留着这一级，就是为了让"融合 ≠ 省带宽"这件事有个可量化的对照。
__global__ void rms_n2(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    float acc = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) {
        float v = xr[i];                       // ← 第一次读
        acc += v * v;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = xr[i] * r * w[i];              // ← 第二次读，同样的地址
}

// ---- N3：x 留在寄存器，只读一次 -------------------------------------------
// 字节：读 x 一次 + 写 y 一次 = 8N/行。相对 N1/N2 的 12N，理论加速 1.5×。
// 代价是每线程多占 MAXS 个寄存器，且单行长度被 BLOCK×MAXS 卡死。
__global__ void rms_n3(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    // 循环必须写成"固定 MAXS 次 + 边界判断"，不能写成 for(i=tid; i<N; i+=BLOCK)
    // 配一个 xs[cnt++]。后者的下标是运行期算出来的，而【寄存器不能动态寻址】——
    // 编译器只好把 xs 放进 local memory（也就是显存），ptxas 会报 spill stores，
    // 这一级"数据留在片上"的前提当场作废。
    // 写成常量下标 xs[c] 并 #pragma unroll，编译器才会把它真正分配到寄存器里。
    float xs[MAXS];
    float acc = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        float v = (i < N) ? xr[i] : 0.0f;      // 越界的线程喂 0，不影响平方和
        xs[c] = v;
        acc += v * v;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i < N) yr[i] = xs[c] * r * w[i];
    }
}

// ---- N4：N3 + float4 -------------------------------------------------------
// 字节数和 N3 完全相同，变的只有指令条数和内存请求数：
// 4 个 32 位 load 并成 1 个 128 位 load。
__global__ void rms_n4(const float *__restrict__ x, const float *__restrict__ w,
                       float *__restrict__ y, int N, float eps) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const int n4 = N >> 2;                     // 一行有多少个 float4

    // reinterpret_cast 把 float* 重新解释成 float4*，地址必须 16 字节对齐 ——
    // cudaMalloc 返回的指针是 256 字节对齐的，而 row*N 只要 N%4==0 就仍然对齐。
    const float4 *xr = reinterpret_cast<const float4 *>(x + row * (long long)N);
    float4       *yr = reinterpret_cast<float4 *>(y + row * (long long)N);
    const float4 *wr = reinterpret_cast<const float4 *>(w);

    float4 xs[MAXV];
    float acc = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        float4 v = (i < n4) ? xr[i] : make_float4(0.f, 0.f, 0.f, 0.f);
        xs[c] = v;
        acc += v.x * v.x + v.y * v.y + v.z * v.z + v.w * v.w;
    }
    const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) continue;
        float4 v = xs[c], g = wr[i], o;
        o.x = v.x * r * g.x;  o.y = v.y * r * g.y;
        o.z = v.z * r * g.z;  o.w = v.w * r * g.w;
        yr[i] = o;
    }
}

// ===========================================================================
//                          online softmax
//                  y_i = exp(x_i − max) / Σ exp(x_j − max)
// ===========================================================================

// ---- S1：三趟，三个 kernel -------------------------------------------------
// 字节：4N + 4N + (4N+4N) = 16N/行
__global__ void sm_s1_max(const float *__restrict__ x, float *__restrict__ mx, int N) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float m = -FLT_MAX;
    for (int i = threadIdx.x; i < N; i += BLOCK) m = fmaxf(m, xr[i]);

    const int lane = threadIdx.x & 31, warp = threadIdx.x >> 5;
    m = warpReduceMax(m);
    if (lane == 0) smem[warp] = m;
    __syncthreads();
    m = (threadIdx.x < BLOCK / 32) ? smem[lane] : -FLT_MAX;
    if (warp == 0) m = warpReduceMax(m);
    if (threadIdx.x == 0) mx[row] = m;
}

__global__ void sm_s1_sum(const float *__restrict__ x, const float *__restrict__ mx,
                          float *__restrict__ sm, int N) {
    __shared__ float smem[BLOCK / 32];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    const float m = mx[row];
    float s = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) s += __expf(xr[i] - m);
    s = blockReduceSum(s, smem);
    if (threadIdx.x == 0) sm[row] = s;
}

__global__ void sm_s1_div(const float *__restrict__ x, const float *__restrict__ mx,
                          const float *__restrict__ sm, float *__restrict__ y, int N) {
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;
    const float m = mx[row], inv = 1.0f / sm[row];
    for (int i = threadIdx.x; i < N; i += BLOCK)
        yr[i] = __expf(xr[i] - m) * inv;
}

// ---- S2：online 递推，两趟 -------------------------------------------------
// 第一趟【一次扫描同时得到 max 和 sum】—— 这就是 online softmax 的全部内容。
// 字节：4N + (4N+4N) = 12N/行
__global__ void sm_s2_ms(const float *__restrict__ x, float *__restrict__ mx,
                         float *__restrict__ sm, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;

    float m = -FLT_MAX, s = 0.0f;
    for (int i = threadIdx.x; i < N; i += BLOCK) {
        float v = xr[i];
        // 递推三行：见到更大的 max，就把已经累好的 s 按比例缩回去
        float m_n = fmaxf(m, v);
        s = s * __expf(m - m_n) + __expf(v - m_n);
        m = m_n;
    }
    blockReduceMaxSum(m, s, smem);
    if (threadIdx.x == 0) { mx[row] = m; sm[row] = s; }
}

// ---- S3：一趟，x 留寄存器 ---------------------------------------------------
// 字节：4N + 4N = 8N/行。相对 S1 的 16N，理论加速 2.0×。
__global__ void sm_s3(const float *__restrict__ x, float *__restrict__ y, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];
    const long long row = blockIdx.x;
    const float *xr = x + row * (long long)N;
    float       *yr = y + row * (long long)N;

    // 常量下标 + #pragma unroll，理由同 rms_n3
    float xs[MAXS];
    float m = -FLT_MAX, s = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= N) { xs[c] = -FLT_MAX; continue; }  // 越界位置塞 -FLT_MAX：
        float v = xr[i];                             // 既不会成为 max，
        xs[c] = v;                                   // exp 出来也是 0
        float m_n = fmaxf(m, v);
        s = s * __expf(m - m_n) + __expf(v - m_n);
        m = m_n;
    }
    blockReduceMaxSum(m, s, smem);
    const float inv = 1.0f / s;
    #pragma unroll
    for (int c = 0; c < MAXS; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i < N) yr[i] = __expf(xs[c] - m) * inv;
    }
}

// ---- S4：S3 + float4 -------------------------------------------------------
__global__ void sm_s4(const float *__restrict__ x, float *__restrict__ y, int N) {
    __shared__ float smem[BLOCK / 32 * 2 + 2];
    const long long row = blockIdx.x;
    const int n4 = N >> 2;
    const float4 *xr = reinterpret_cast<const float4 *>(x + row * (long long)N);
    float4       *yr = reinterpret_cast<float4 *>(y + row * (long long)N);

    float4 xs[MAXV];
    float m = -FLT_MAX, s = 0.0f;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) { xs[c] = make_float4(-FLT_MAX, -FLT_MAX, -FLT_MAX, -FLT_MAX); continue; }
        float4 v = xr[i];
        xs[c] = v;
        // 一次进来 4 个元素，先在寄存器里把这 4 个合成一个 (m,s)，再并进累计值。
        // 这已经是 FlashAttention 分块合并的最小形态了 —— 只不过块大小是 4。
        float mv = fmaxf(fmaxf(v.x, v.y), fmaxf(v.z, v.w));
        float sv = __expf(v.x - mv) + __expf(v.y - mv) + __expf(v.z - mv) + __expf(v.w - mv);
        float m_n = fmaxf(m, mv);
        s = s * __expf(m - m_n) + sv * __expf(mv - m_n);
        m = m_n;
    }
    blockReduceMaxSum(m, s, smem);
    const float inv = 1.0f / s;
    #pragma unroll
    for (int c = 0; c < MAXV; ++c) {
        int i = threadIdx.x + c * BLOCK;
        if (i >= n4) continue;
        float4 v = xs[c], o;
        o.x = __expf(v.x - m) * inv;  o.y = __expf(v.y - m) * inv;
        o.z = __expf(v.z - m) * inv;  o.w = __expf(v.w - m) * inv;
        yr[i] = o;
    }
}

// ===========================================================================
//                         CPU 参照与抽样校验
// ===========================================================================
enum Kind { K_N1, K_N2, K_N3, K_N4, K_S1, K_S2, K_S3, K_S4 };
static bool isNorm(Kind k) { return k <= K_N4; }

// 只抽查若干行。全查的话 M=4096、N=3584 要在 CPU 上算 1400 万次 exp，太慢。
static int verifyRows(Kind kind, int M, int N, const std::vector<float> &hx,
                      const std::vector<float> &hw, const std::vector<float> &hy,
                      int nrows) {
    std::mt19937 rng(20260925);
    int bad = 0;
    for (int t = 0; t < nrows; ++t) {
        long long row = rng() % (unsigned)M;
        const float *xr = hx.data() + row * (long long)N;
        const float *yr = hy.data() + row * (long long)N;

        std::vector<double> ref(N);
        if (isNorm(kind)) {
            double acc = 0.0;
            for (int i = 0; i < N; ++i) acc += (double)xr[i] * xr[i];
            double r = 1.0 / std::sqrt(acc / N + 1e-6);
            for (int i = 0; i < N; ++i) ref[i] = xr[i] * r * hw[i];
        } else {
            double m = -1e300;
            for (int i = 0; i < N; ++i) m = std::max(m, (double)xr[i]);
            double s = 0.0;
            for (int i = 0; i < N; ++i) s += std::exp(xr[i] - m);
            for (int i = 0; i < N; ++i) ref[i] = std::exp(xr[i] - m) / s;
        }
        // __expf / rsqrtf 是快速近似指令，容差要比普通浮点宽一点。
        // 这里用相对误差 2e-3，softmax 的绝对值很小，再加一个 1e-7 的绝对兜底。
        for (int i = 0; i < N; ++i) {
            double d = std::fabs(ref[i] - yr[i]);
            if (d > 2e-3 * std::fabs(ref[i]) + 1e-7) {
                if (bad < 3)
                    printf("  行 %lld 列 %d: GPU %.6g  CPU %.6g\n", row, i, yr[i], ref[i]);
                ++bad;
            }
        }
    }
    return bad;
}

// ===========================================================================
//                                main
// ===========================================================================
int main(int argc, char **argv) {
    if (argc < 2) {
        printf("用法: %s <kernel> [M] [N] [ITERS]\n"
               "  kernel = n1|n2|n3|n4   RMSNorm     默认 M=4096 N=3584\n"
               "           s1|s2|s3|s4   softmax     默认 M=4096 N=2048\n"
               "  M = 行数（token 数 / 打分矩阵的行数），N = 每行长度\n"
               "  例： %s n4 4096 3584 11      Qwen2.5-7B 的一次 RMSNorm\n"
               "       %s n4 1 3584 11         decode batch=1（只有 1 个 block！）\n"
               "       %s s4 114688 2048 11    28 头 × 4096 个 query 的打分\n",
               argv[0], argv[0], argv[0], argv[0]);
        return 2;
    }
    const char *name = argv[1];
    Kind kind;
    if      (!strcmp(name, "n1")) kind = K_N1;
    else if (!strcmp(name, "n2")) kind = K_N2;
    else if (!strcmp(name, "n3")) kind = K_N3;
    else if (!strcmp(name, "n4")) kind = K_N4;
    else if (!strcmp(name, "s1")) kind = K_S1;
    else if (!strcmp(name, "s2")) kind = K_S2;
    else if (!strcmp(name, "s3")) kind = K_S3;
    else if (!strcmp(name, "s4")) kind = K_S4;
    else { printf("不认识的 kernel: %s\n", name); return 2; }

    int M     = (argc > 2) ? atoi(argv[2]) : 4096;
    int N     = (argc > 3) ? atoi(argv[3]) : (isNorm(kind) ? 3584 : 2048);
    int ITERS = (argc > 4) ? atoi(argv[4]) : 11;
    if (M <= 0 || N <= 0) { printf("M/N 必须为正\n"); return 2; }

    cudaDeviceProp prop;
    CUDA_CHECK(cudaGetDeviceProperties(&prop, 0));
    int memClkKHz = 0, gpuClkKHz = 0;
    cudaDeviceGetAttribute(&memClkKHz, cudaDevAttrMemoryClockRate, 0);
    cudaDeviceGetAttribute(&gpuClkKHz, cudaDevAttrClockRate, 0);
    // 峰值带宽 = 内存时钟 × 2（DDR 双沿）× 位宽/8。和 sgemm_all.cu 用同一个口径。
    const double peakBW = memClkKHz * 2.0 * (prop.memoryBusWidth / 8) / 1.0e6;

    printf("GPU: %s  sm_%d%d  %d SM  L2 %.1f MB   显存带宽峰值 %.0f GB/s\n",
           prop.name, prop.major, prop.minor, prop.multiProcessorCount,
           prop.l2CacheSize / 1048576.0, peakBW);
    printf("[%s] %s   M=%d 行 × N=%d 列   block %d 线程   grid %d 个 block\n",
           name, isNorm(kind) ? "RMSNorm" : "softmax", M, N, BLOCK, M);

    // ---- 两个会让结果作废的前提，先查 ----
    const bool needReg = (kind == K_N3 || kind == K_N4 || kind == K_S3 || kind == K_S4);
    if (needReg && N > BLOCK * MAXS) {
        printf("✗ 这一级把整行存在寄存器里，单行最长 %d，而 N=%d。\n",
               BLOCK * MAXS, N);
        printf("  这不是实现偷懒，是硬件约束 —— 也正是 FlashAttention 必须分块的原因，\n"
               "  详见导学 §7 · 三。想跑长行请用 n1/n2 或 s1/s2。\n");
        return 3;
    }
    const bool needVec4 = (kind == K_N4 || kind == K_S4);
    if (needVec4 && (N & 3)) {
        printf("✗ float4 版要求 N 是 4 的倍数（当前 N=%d）\n", N);
        return 3;
    }

    // ---- 数据 ----
    const size_t nElem = (size_t)M * N;
    const size_t bytes = nElem * sizeof(float);
    std::vector<float> hx(nElem), hw(N), hy(nElem);
    std::mt19937 rng(12345);
    std::uniform_real_distribution<float> dist(-3.0f, 3.0f);
    for (size_t i = 0; i < nElem; ++i) hx[i] = dist(rng);
    for (int i = 0; i < N; ++i)        hw[i] = 0.5f + 0.5f * dist(rng) / 3.0f;

    float *dx = nullptr, *dw = nullptr, *dy = nullptr, *dm = nullptr, *ds = nullptr;
    CUDA_CHECK(cudaMalloc(&dx, bytes));
    CUDA_CHECK(cudaMalloc(&dy, bytes));
    CUDA_CHECK(cudaMalloc(&dw, N * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&dm, M * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&ds, M * sizeof(float)));
    CUDA_CHECK(cudaMemcpy(dx, hx.data(), bytes, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(dw, hw.data(), N * sizeof(float), cudaMemcpyHostToDevice));

    const float eps = 1e-6f;
    // lambda：把"发射这一级的全部 kernel"打包成一个可重复调用的东西。
    // [&] 表示按引用捕获外面所有用到的变量。
    auto launch = [&]() {
        switch (kind) {
            case K_N1: rms_n1_pass1<<<M, BLOCK>>>(dx, dm, N, eps);
                       rms_n1_pass2<<<M, BLOCK>>>(dx, dw, dm, dy, N);          break;
            case K_N2: rms_n2<<<M, BLOCK>>>(dx, dw, dy, N, eps);               break;
            case K_N3: rms_n3<<<M, BLOCK>>>(dx, dw, dy, N, eps);               break;
            case K_N4: rms_n4<<<M, BLOCK>>>(dx, dw, dy, N, eps);               break;
            case K_S1: sm_s1_max<<<M, BLOCK>>>(dx, dm, N);
                       sm_s1_sum<<<M, BLOCK>>>(dx, dm, ds, N);
                       sm_s1_div<<<M, BLOCK>>>(dx, dm, ds, dy, N);             break;
            case K_S2: sm_s2_ms <<<M, BLOCK>>>(dx, dm, ds, N);
                       sm_s1_div<<<M, BLOCK>>>(dx, dm, ds, dy, N);             break;
            case K_S3: sm_s3<<<M, BLOCK>>>(dx, dy, N);                         break;
            case K_S4: sm_s4<<<M, BLOCK>>>(dx, dy, N);                         break;
        }
    };

    // ---- occupancy：这一级理论上每个 SM 能同时跑几个 block ----
    int blocksPerSM = 0;
    const void *rep = (kind == K_N1) ? (const void *)rms_n1_pass1
                    : (kind == K_N2) ? (const void *)rms_n2
                    : (kind == K_N3) ? (const void *)rms_n3
                    : (kind == K_N4) ? (const void *)rms_n4
                    : (kind == K_S1) ? (const void *)sm_s1_max
                    : (kind == K_S2) ? (const void *)sm_s2_ms
                    : (kind == K_S3) ? (const void *)sm_s3
                                     : (const void *)sm_s4;
    CUDA_CHECK(cudaOccupancyMaxActiveBlocksPerMultiprocessor(&blocksPerSM, rep, BLOCK, 0));
    printf("occupancy: %d block × %d 线程 = %d / %d = %.1f%%",
           blocksPerSM, BLOCK, blocksPerSM * BLOCK, prop.maxThreadsPerMultiProcessor,
           100.0 * blocksPerSM * BLOCK / prop.maxThreadsPerMultiProcessor);
    // grid 太小的话，占用率再高也没用 —— 卡根本没被填满。这是 decode 的常态。
    const double smFill = (double)M / (prop.multiProcessorCount * blocksPerSM);
    printf("   grid 填充度 %d / (%d SM × %d) = %.2f%s\n",
           M, prop.multiProcessorCount, blocksPerSM, smFill,
           smFill < 1.0 ? "   ⚠ 填不满，卡在空转" : "");

    printf("footprint = x + y = %.1f MB（L2 %.1f MB）%s\n",
           2.0 * bytes / 1048576.0, prop.l2CacheSize / 1048576.0,
           2.0 * bytes > prop.l2CacheSize ? "  → 装不下，必须走显存"
                                          : "  ⚠ 装得下 → 数字会虚高");

    // ---- 计时：和 sgemm_all.cu 同一套（预热 + 中位数）----
    const int WARMUP = (ITERS <= 1) ? 0 : (ITERS <= 2 ? 1 : 3);
    for (int i = 0; i < WARMUP; ++i) launch();
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaDeviceSynchronize());

    cudaEvent_t ev0, ev1;
    CUDA_CHECK(cudaEventCreate(&ev0));
    CUDA_CHECK(cudaEventCreate(&ev1));
    std::vector<float> samples;
    for (int it = 0; it < ITERS; ++it) {
        CUDA_CHECK(cudaEventRecord(ev0));
        launch();
        CUDA_CHECK(cudaEventRecord(ev1));
        CUDA_CHECK(cudaEventSynchronize(ev1));
        float t; CUDA_CHECK(cudaEventElapsedTime(&t, ev0, ev1));
        samples.push_back(t);
    }
    std::sort(samples.begin(), samples.end());
    const size_t ns = samples.size();
    const double ms = (ns % 2) ? samples[ns / 2]
                               : 0.5 * (samples[ns / 2 - 1] + samples[ns / 2]);

    CUDA_CHECK(cudaMemcpy(hy.data(), dy, bytes, cudaMemcpyDeviceToHost));
    const int bad = verifyRows(kind, M, N, hx, hw, hy, 8);
    printf("%s（抽查 8 行）\n", bad == 0 ? "✓ 抽样校验通过" : "✗ 抽样校验失败");

    // ---- 字节账：这是这两个算子唯一重要的一本账 ----
    // 每行搬多少字节，按"必须经过显存的量"算。权重 w 只有 4N 字节，
    // 所有行共用、稳稳待在 L2 里，不计入。
    double bytesPerRow;
    switch (kind) {
        case K_N1: case K_N2: bytesPerRow = 12.0 * N; break;   // 读两次 + 写一次
        case K_N3: case K_N4: bytesPerRow =  8.0 * N; break;   // 读一次 + 写一次
        case K_S1:            bytesPerRow = 16.0 * N; break;   // 读三次 + 写一次
        case K_S2:            bytesPerRow = 12.0 * N; break;
        default:              bytesPerRow =  8.0 * N; break;
    }
    const double moved = bytesPerRow * M;
    const double gbps  = moved / (ms / 1000.0) / 1.0e9;
    const double mbu   = 100.0 * gbps / peakBW;

    printf("中位耗时 %.4f ms   搬运 %.1f MB   %.1f GB/s   MBU %.1f%%\n",
           ms, moved / 1048576.0, gbps, mbu);
    printf("字节账: %.0fN 字节/行 × %d 行 = %.1f MB；"
           "理论下限 %.4f ms（按 %.0f GB/s 跑满）\n",
           bytesPerRow / N, M, moved / 1048576.0,
           moved / (peakBW * 1e9) * 1000.0, peakBW);

    CUDA_CHECK(cudaFree(dx)); CUDA_CHECK(cudaFree(dy)); CUDA_CHECK(cudaFree(dw));
    CUDA_CHECK(cudaFree(dm)); CUDA_CHECK(cudaFree(ds));
    return bad == 0 ? 0 : 1;
}

三、compute-sanitizer 在查什么：读懂 racecheck 日志↑

compute-sanitizer 是 CUDA 自带的运行时检查工具。 它照常运行你的程序，同时监控每一条访存指令。

这里用的是它的 racecheck 工具，只查一类错误：shared memory 上的竞态。 同时满足下面三个条件，就是一处竞态：

  • 同一个 block 里的两个线程，访问同一个 shared memory 地址；
  • 两次访问中，至少有一次是写；
  • 两次访问之间，没有 __syncthreads()。

一、为什么需要它：抽样校验抓不住竞态

漏写 __syncthreads() 不会让程序崩溃，也不会报错。 它只会让结果偏一点点。偏多少取决于 warp 的执行顺序。 换一个形状或换一张卡，结果可能就不同。 所以「✓ 抽样校验通过」不能证明没有竞态。 这一次结果对，可能只是执行顺序碰巧合适。

racecheck 不看结果对不对，只看访问顺序。 只要访问顺序满足上面三个条件，它就报告一处竞态，哪怕这次读到的值碰巧正确。 racecheck 把每一处竞态记为一个 hazard，按读写的先后分三类：

racecheck 报告的三类 hazard
类型含义在 blockReduceSum 里的例子
RAWRead-After-Write 线程 B 要读线程 A 写的新值，但 A 可能还没写 删掉同步点 ⑥：1–7 号 warp 读 smem[0] 时，0 号线程可能还没写入
WARWrite-After-Read 线程 B 还没读完旧值，线程 A 就把它覆盖了 同一个 kernel 连续做两次归约：第二次的 ② 可能覆盖第一次还没读完的 smem[0]
WAWWrite-After-Write 两个线程写同一个地址，最后留下哪个值不确定 把 smem[warp] 错写成 smem[lane]：8 个 warp 的 lane 0 都写 smem[0]

二、对照源码：racecheck 检查哪几行

下面是 fused_ops.cu 里的 blockReduceSum，n3 用的就是它。 注释说明 racecheck 怎样看每一行。 蓝色是 shared memory 访问； 红色是 __syncthreads()，删掉任何一个，racecheck 都会报告竞态。 

__inline__ __device__ float blockReduceSum(float v, float *smem) {
    const int lane = threadIdx.x & 31;
    const int warp = threadIdx.x >> 5;
    v = warpReduceSum(v);                // warp 内用 shuffle 交换，数据在寄存器里，racecheck 不检查
    if (lane == 0) smem[warp] = v;       // ② 写：8 个线程各写一个槽 smem[0..7]，地址不重叠，没有 WAW
    __syncthreads();                     // ③ 同步：删掉它，smem[1..7] 报 RAW
                                         //    （0 号 warp 读的时候，7 号 warp 可能还没写）
    v = (threadIdx.x < (BLOCK >> 5)) ? smem[lane] : 0.0f;
                                         // ④ 读：只有 0 号 warp 的前 8 个线程读
    if (warp == 0) v = warpReduceSum(v);
    if (threadIdx.x == 0) smem[0] = v;   // ⑤ 写回 smem[0]：④ 里读 smem[0] 的也是 0 号线程
                                         //    同一个线程先读后写，不算竞态，所以这里不需要同步
    __syncthreads();                     // ⑥ 同步：删掉它，smem[0] 报 RAW
                                         //    （其余 255 个线程可能读到 ② 写入的部分和）
    return smem[0];                      // ⑦ 读：256 个线程读同一个地址，只读不写，没有竞态
}

blockReduceMaxSum（s3 和 s4 用）把结果写到单独的槽

它把最终结果写进 smem[2*nwarp] 和 smem[2*nwarp+1]，不覆盖 smem[0]。 部分和占 smem[0..15]（m 和 s 各 8 个），最终结果占另外两个槽。 读部分和与写最终值的地址不重叠，所以不需要像 ⑤ 那样依赖「同一个线程」来保证安全。 这种写法更不容易出错。

四、为什么只测三个 kernel，为什么形状这么小

run_fused.sh 第 5 段的四个取舍
取舍原因
只测 n3 s3 s4 竞态只可能出现在 block 级归约里。n3 代表 blockReduceSum（n4 用同一个函数）； s3、s4 代表 blockReduceMaxSum（s4 是它的 float4 版）。
M=8 N=1000，只跑 1 次 racecheck 让程序慢几百倍，用主基准的 8192 行跑不完。 竞态发生在 block 内部，每个 block 执行的代码相同。 所以 8 个 block 和 8192 个 block 检查到的代码路径相同。
N=1000 1000 不是 256 的整数倍，所以每行末尾的边界分支也会被执行到。
放在计时之后 racecheck 很慢，结果只有「0」和「非 0」两种。 放在最后，机器上没装 compute-sanitizer 时只跳过这一段，前面的性能数据不受影响。

racecheck 不检查的错误

racecheck 只检查 shared memory。 其他错误要换用同一个程序的其他工具：

错误工具
全局内存越界--tool memcheck（默认）
读到未初始化的数据--tool initcheck
__syncthreads() 放在了不是所有线程都会执行的分支里--tool synccheck

warp 内的 __shfl_xor_sync 只在寄存器之间交换数据， 不经过 shared memory，所以也不在检查范围内。

小结：三项检查各回答一个问题。

  • 计时：kernel 快不快。
  • 抽样校验：这一次结果对不对。
  • racecheck：结果对，是不是只因为执行顺序碰巧合适。

三段都是 0 hazards，说明 blockReduceSum 和 blockReduceMaxSum 里的 __syncthreads() 位置正确。

#!/usr/bin/env bash
# =============================================================================
# run_fused.sh —— RMSNorm / online softmax 两条融合阶梯的完整测试
#
#   八个 kernel：n1 n2 n3 n4（RMSNorm）+ s1 s2 s3 s4（softmax）
#
#   和 SGEMM 那套的区别：这两个算子是【访存密集】的，
#   所以看的不是"占峰值算力"，是 MBU = 实测 GB/s ÷ 1008。
#
#   阶段：
#     0 编译 + spill 检查   ← 这一步比 SGEMM 那边更要命，见下面
#     1 正确性（含边界）
#     2 主阶梯（固定形状，看 1.5× 和 2.0× 兑现了多少）
#     3 形状扫描（decode b1 / b32 / prefill / 大批）
#     4 长行：寄存器放不下会怎样
#     5 竞态检查
#
#   ⚠ 第 0 步的 spill 检查是这份测试的命门：
#     n3/n4/s3/s4 的全部立论就是"整行留在寄存器里，只读一次 global"。
#     一旦 ptxas 报 spill stores，那行数据其实被挪到了 local memory（也就是显存），
#     于是它们退化成"读两次"，1.5× 和 2.0× 都不会出现，而且你从耗时上看不出原因。
#
#   用法：bash run_fused.sh
#         ROUNDS=1 bash run_fused.sh      # 快速过一遍
# =============================================================================
#
# ---- 给不熟悉 shell 的读者：这份脚本用到的语法，一次讲清 --------------------
#
#   #!/usr/bin/env bash  第一行的 #! 叫 shebang，告诉系统拿哪个解释器跑这个文件。
#                      写 env bash 而不是写死 /bin/bash，是为了用 PATH 里找到的那个。
#   #                  行内从 # 到行尾都是注释（shebang 那一行除外）。
#   $VAR / ${VAR}      取变量的值。${} 是为了和紧跟的字符分开，
#                      比如 "fused_${STAMP}.txt" —— 不加花括号会被当成变量名 STAMP.txt。
#   "$VAR"             几乎永远要加双引号 —— 不加的话，值里有空格就会被拆成多个参数。
#                      下面只有一处故意不加（set -- $shp），那里就是要它拆开。
#   ${VAR:-默认值}      VAR 没设置或为空时取「默认值」。ROUNDS=${ROUNDS:-3} 的意思是：
#                      允许调用者用 ROUNDS=1 bash run_fused.sh 从环境覆盖它。
#   $(命令)             命令替换：先跑命令，把它打印的内容替换到这里。
#   名字() { ...; }     定义函数。调用时直接写名字，第 1、2 个参数是 $1 $2 …
#                      函数体写在一行时，最后一条命令后面也要有分号，} 前要有空格。
#   "$@"  与  "$*"     都表示"全部参数"，但用途相反：
#                      "$@" 保持每个参数各自独立 → 拿来【执行】；
#                      "$*" 拼成一整串           → 拿来【打印】。下面 run() 里两个都用到了。
#   cmd1 | cmd2        管道：把 cmd1 的输出喂给 cmd2 的输入。
#   >  文件            把输出写进文件（覆盖）；  >>  是追加。
#   2>/dev/null        把「错误输出」丢掉（1 是正常输出，2 是错误输出）。
#   2>&1               把错误输出并进正常输出，这样管道和重定向才收得到它。
#   \$                 反斜杠转义，输出一个字面的 $ 符号，而不是去取变量。
#   for x in 一串词     按空格逐个取出。词可以来自字面量、变量展开或 $( )。
#   do … done          for / while 的循环体；if 用 then … fi 收尾。
#   A || { B; }        A 失败（返回非 0）时才执行 B。A && B 则相反。
#                      { } 把多条命令打包成一组（注意最后一条也要有分号）。
#   set -u             用到没定义过的变量就立刻报错退出，防手滑打错变量名。
#   set -- 词 词       重设位置参数：执行后 $1 $2 就变成这些词。
#                      下面拿它把 "prefill 2048" 这种「名字+数值」的配对拆成两个变量。
#   command -v xxx     查「系统里有没有 xxx 这个命令」，输出丢掉只看成败。
#   exit 1             中止脚本并返回非 0（约定：0 成功，非 0 失败）。
#
#   ---- 被测程序的调用约定 ----
#   ./fused_ops <kind> <M> <N> <iters>
#       kind   n1|n2|n3|n4|s1|s2|s3|s4
#       M      行数（= batch × seq，每行一个 block）
#       N      列数（RMSNorm 用 hidden=3584，softmax 用 seq=2048）
#       iters  计时重复次数，程序取中位数
#
# =============================================================================
set -u

ROUNDS=${ROUNDS:-3}
HID=${HID:-3584}                          # Qwen2.5-7B 的 hidden_size

STAMP=$(date +%Y%m%d_%H%M%S)
OUT="fused_${STAMP}.txt"                  # ${STAMP} 的花括号是为了和后面的 .txt 分开

#        tee 同时写屏幕和文件，-a 表示追加（没有 -a 会每次清空）
# rule： 固定打一条横线，纯粹为了日志好读
# run：  先把命令行原样记进日志（方便复现），再真正执行它。函数体是两条命令，用 ; 隔开：
#          echo "\$ $*" >>"$OUT"     ← 记日志的是这半句。\$ 输出字面的 $ 符号（模仿终端提示符），
#                                      $* 把全部参数拼成一行；>> 只写文件、不上屏幕
#          "$@" 2>&1 | tee -a "$OUT" ← 这半句才是真执行。"$@" 保持每个参数独立
#                                      （$* 会拼成一整串，不能拿来执行）；2>&1 让报错也进日志
log()  { echo "$@" | tee -a "$OUT"; }

一把尺子量穿五条：重用距离

字节账算的是「kernel 发出了多少访存请求」，而耗时取决于「DRAM 实际被读写了多少」。 这两个数之间隔着一层 72 MiB 的 L2。 同一行数据被读第二次时，这两次之间隔了多少数据 —— 这个距离叫重用距离。它小于 L2 容量，第二次读就不花钱。

图 31 · 条的长度是示意，不是等比 —— 要看的是它们落在虚线的哪一侧。 N1 和 N2 的代码字节账一模一样（都读 x 两次）， 差别只在两次读之间隔了多远。

① N2 为什么快了 1.49×

把 N3 实测到的 917.5 GB/s 当作这张卡的 DRAM 实际天花板 （峰值 1008 GB/s 的 91.0%，八级里七级都贴着它跑）， 用「耗时 × 917.5 GB/s」反推每一级真正搬了多少，再和账面对一下：

// rms_n2：两次读之间，这个 block 只处理了自己这一行
for (int i = threadIdx.x; i < N; i += BLOCK) {
    float v = xr[i];                       // 第一次读，3584 个 float = 14 KB
    acc += v * v;
}
const float r = rsqrtf(blockReduceSum(acc, smem) / N + eps);
for (int i = threadIdx.x; i < N; i += BLOCK)
    yr[i] = xr[i] * r * w[i];              // 第二次读，几微秒后，同样 14 KB

// rms_n1：pass1 读完【全部 8192 行 = 112 MiB】，kernel 结束，
//         pass2 才从头再读一遍 —— 那时 72 MiB 的 L2 早被后面的行挤干净了

所以预测 ① 错在哪：它默认「访存指令发出的字节」就是「DRAM 搬运的字节」。 实测里 N2（0.2591 ms）和 N3（0.2560 ms）只差 1.2% —— 因为它俩对 DRAM 来说都是 8N， 区别仅在 N2 多发了一遍 L2 读请求。

这条落空比成立值钱

融合确实省带宽 —— 但省的机制不是「少发访存指令」， 而是「把重用距离压缩到 cache 装得下」。 N1→N2 没动任何一条 load 指令的数量，只是把两次 load 挪进了同一个 block， 重用距离就从 112 MiB 塌到 14 KB。 这正是 FlashAttention 的全部赌注： 它也没有减少对 Q/K/V 的读次数，减少的是两次读之间隔了多远。

这一轮实验真正留下的三句话

① 字节账要算「到 DRAM 的字节」，不是「指令发出的字节」。 两者之间隔着一层 cache，差距可以有 1.5 倍。

② 决定第二次访问花不花钱的，是重用距离，不是访问次数。 融合、分块、寄存器驻留，三种手法压缩的都是同一个量。

③ 选基准形状时要先看数据装不装得进 L2。 M=8192 的 softmax 刚好卡在 64 MiB / 72 MiB 这条线上， 四条预测里有三条是被它绊倒的。 换成 M=16384，理论值立刻兑现。

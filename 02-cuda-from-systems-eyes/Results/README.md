## 两份 CSV 的分工

| | 内容 | 用途 |
|---|---|---|
| `bench_<stamp>.csv` | 每一轮每个 kernel 一行，不做任何聚合 | **证据**。"你这 3 轮抖了多少"的答案只在这里 |
| `bench_<stamp>_median.csv` | 跨轮中位数，多一列 `ms_spread_pct` | **结论**。报告里所有表和图都引这一份 |

> **逐轮表只做搬运** —— `bench_<stamp>.csv` 里每个数都能在原文里逐字找到。
>
> **中位表有算出来的列**，分两类：聚合（`ms` 的中位数、`ms_spread_pct`），
> 以及由中位耗时**重算**的派生列（`gflops` / `pct_peak` / `beat` /
> `cyc_per_load` / `roofline_pct`）。
> 后者必须重算而不能照抄第 1 轮 —— 中位数不一定来自第 1 轮，照抄会让
> "`ms` 和由 `ms` 推出来的数"自相矛盾。
> *这个坑真踩过：k1 的 `ms` 取自第 3 轮，节拍却留着第 1 轮的 31.76，
> 而用中位耗时算出来是 31.83，报告里印出的算式自己和自己不符。*
>
> 结构性的列（`dist` / `bcast` / `ldg` / `ai` / `regs` / `occ`）各轮完全相同，照抄第 1 轮。

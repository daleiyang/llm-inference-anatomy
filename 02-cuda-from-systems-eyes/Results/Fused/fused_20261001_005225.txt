>>> 十一个 kernel 全都要是 0 bytes stack frame / 0 bytes spill stores。
>>> 尤其盯住 rms_n3 / rms_n4 / sm_s3 / sm_s4 —— 它们每线程要拿 32 个寄存器
>>> 存整行数据。一旦 spill，那行数据就跑到显存里去了，
>>> '只读一次' 的前提作废，1.5× / 2.0× 一个都不会出现。
>>> 顺带记下寄存器数：n1/n2 应该很少（十几个），n3/n4/s3/s4 应该明显更多。

 长行：寄存器放不下的时候
   Qwen2.5-7B 的 vocab 是 152064 —— 采样时要对这么长的一行做 softmax。
   而 s3/s4 的单行上限是 BLOCK × MAXS = 256 × 32 = 8192。
   下面三条命令里，前两条能跑，第三条会被程序拒绝并说明原因。

   这不是实现偷懒，而是【FlashAttention 为什么必须分块】的同一个约束：
   行放不进片上存储 → 必须分块 → 分块就要能增量合并 softmax
   → 于是 online 递推从'优化技巧'变成'必需品'。
=============================================================
